Звук: два шага оцифровки

1. Дискретизация

Измеряем через равные интервалы времени.

fs — отсчётов в секунду на канал.

2. Квантование

Округляем амплитуду до доступного уровня.

b бит → 2b кодов.

15–17 мин. Схема качественная. Частота дискретизации отвечает за моменты измерения, разрядность — за набор возможных уровней. Это независимые параметры.

PCM: последовательность отсчётов

V = fs × b × c × t бит

  • fs — частота дискретизации, Гц.
  • b — бит на один отсчёт.
  • c — число каналов.
  • t — длительность, секунды.

Стерео = 2 канала

Левый и правый потоки отсчётов.

Для ограниченного спектра fs > 2fmax; перед оцифровкой нужен фильтр.

17–19 мин. Формула для несжатого PCM без заголовков и дополнительного выравнивания. Теорему отсчётов только обозначить. Разрядность не следует путать с частотой.

Десять секунд стереозвука

48 000 Гц · 16 бит · 2 канала · 10 секунд

48 000 × 16 × 2 × 10 / 8 = 1 920 000 байт

1.92 MB

Вопрос: что изменится при переходе в моно?

Объём уменьшится вдвое. Частота каждого канала не изменится.

«Длина строки» — какая именно?

  • Байты: сколько занимает закодированный текст.
  • Кодовые единицы: элементы UTF-8 или UTF-16.
  • Кодовые точки: значения Unicode.
  • Видимые знаки: могут состоять из нескольких кодовых точек.

Для UTF-8-строки «AЯ» результат равен 3.
28–30 мин. Пример видимого знака — буква с комбинируемым ударением. Тип char не устанавливает кодировку. Для хранения AЯ с завершающим нулём нужно четыре байта.

Прямой код: знак и модуль

1знак «−»01001017 бит модуля · значение 37

В 8-битном прямом коде модулю доступны только 7 бит:

−37 → 1 | 0100101 → 10100101

Диапазон: −127…+127. Два нуля:
00000000 и 10000000.

32–34 мин. Итого восемь бит: один знаковый и семь для модуля. Наличие отдельного знака усложняет арифметику модулей.

Обратный код: инверсия +37

+37           00100101
инверсия      11011010   ← код −37

Инвертируем все биты положительного модуля в полной сетке.

Не прямой код уже отрицательного числа!

Диапазон: −127…+127.

Два нуля: 00…0, 11…1.

Сложение требует циклического переноса из старшего разряда в младший.

34–35 мин. Обратный код −37 — 218 как unsigned. Циклический перенос только упомянуть, основной рабочий формат дальше — дополнительный.

Дополнительный код: инверсия + 1

+37           00100101
инверсия      11011010
плюс 1        11011011   ← код −37

28 − 37 = 219

Тот же код: 11011011.

Один ноль.

Обычное двоичное сложение.
Сохраняем n младших битов.

35–37 мин. Показать два способа получения кода. Формула 2^n−|x| для отрицательного представимого числа. В современных распространённых CPU именно этот код используется для signed-целых.

Как прочитать дополнительный код?

Пусть u — значение тех же битов как unsigned.

Старший бит 0

x = u

00100101 → 37

Старший бит 1

x = u − 2n

11011011 → 219 − 256 = −37

Старший бит имеет вес −2n−1, остальные — обычные положительные веса.

37–38 мин. Метод u−2^n часто проще обратной инверсии. Подставить 11111111: 255−256=−1. Подставить 10000000: 128−256=−128.

38–40 мин. Общий диапазон дополнительного кода: −2^(n−1)…2^(n−1)−1. Почему комбинаций одинаково, а разных значений в прямом коде меньше? Два кода нуля.

Код со смещением

code = x + bias

8 бит, bias = 128:

−37 → 91  → 01011011
  0 → 128 → 10000000
+37 → 165 → 10100101

Обратно

x = code − bias.

Старший бит здесь не работает как знак прямого кода.

Такой подход используется для порядка в IEEE 754.

40–41 мин. Bias выбирается форматом. Диапазон при bias 128 — −128…127. Для сложения кодов нужна поправка на bias: code(a+b)=code(a)+code(b)−bias при представимой сумме.

Машинная сетка и язык C

  • В n-битной сетке сохраняем n младших битов.
  • В C малые целые типы сначала проходят integer promotions.
  • Беззнаковая арифметика C — по модулю.
  • Переполнение знакового сложения C — неопределённое поведение.

Нельзя переносить все свойства 8-битной схемы

Кодируем −12.625: знак и порядок

  1. Число отрицательное: s = 1.
  2. Модуль: 1100.101₂.
  3. Нормализация: 1.100101₂ × 2³.
  4. Истинный порядок E = 3.
  5. Хранимый: e = 3 + 127 = 130 = 10000010₂.

Порядок хранится со смещением, а не в дополнительном коде.

Убираем ведущую 1, дополняем поле дроби нулями.

Проверка: −(1 + 1/2 + 1/16 + 1/64) × 8 = −12.625.

Это запись слова. В little-endian памяти байты: 00 00 4A C1.

67–69 мин. Формула шага относится к нормальным диапазонам с −126 ≤ E ≤ 127. У субнормальных binary32 шаг постоянный: 2^-149. Относительная точность примерно постоянна в normal-диапазоне, абсолютная меняется с масштабом. При больших значениях теряется возможность представлять все целые подряд.

Точно

0.1 = 1/10

Обычный режим: к ближайшему; при равенстве — к чётному.

69–71 мин. Десятичное число может быть коротким в десятичной записи и бесконечным в двоичной. Это не ошибка процессора, а ограничение представления.

71–73 мин. Чётность относится к младшему биту significand, а не к десятичной целой части. Первая строка не является ничьей, её нельзя округлять вверх по правилу для второго примера.

Три последствия конечной точности

  • Поглощение: в binary32 224 + 1 округляется к 224.
  • Неассоциативность: порядок вычислений может менять результат.
  • Вычитание близких приближений: относительная ошибка может вырасти.

Для приближённого сравнения задаём допуски по задаче.
Машинный ε не является универсальным допуском.

Точное равенство допустимо, когда нужно проверить именно равенство.

Сложение и вычитание: алгоритм

  1. Выравниваем порядки, сдвигая меньшую значащую часть вправо.
  2. Сохраняем дополнительные биты для округления.
  3. Складываем или вычитаем значащие части с учётом знаков.
  4. Нормализуем результат и корректируем порядок.
  5. Округляем; проверяем особые случаи.

После вычитания нормализация может потребовать
сдвига влево на несколько разрядов.

Умножение значащих частей

(M₁ × 2E₁) × (M₂ × 2E₂) = (M₁M₂) × 2E₁+E₂

  1. Перемножаем значащие части; знак — XOR знаков.
  2. Складываем истинные порядки.
  3. Если произведение ≥ 2, сдвигаем вправо на 1 и увеличиваем порядок.
  4. Округляем до доступной точности.

1.5 × 2.5 = (1.1₂ × 1.01₂) × 2¹ = 1.111₂ × 2¹ = 3.75

Дополнительно, 3 мин. Значащие части normal лежат в [1,2), произведение — в [1,4). Если складывать хранимые порядки, нужно корректировать bias.

Умножение с округлением

1.75 × 2.5 = 4.375 = 1.00011₂ × 2²

Оставляем 4 бита дроби: 1.0001 | 1.

Ровно середина → результат 4.5.

Дополнительно, 2 мин. Отбрасываемая часть равна половине шага, а не больше половины. Проверить расстояния: 0.125 в обе стороны.

Деление: обратная работа с порядками

(M₁ × 2E₁) / (M₂ × 2E₂) = (M₁ / M₂) × 2E₁−E₂

  • Делим значащие части и вычитаем истинные порядки.
  • Если частное меньше 1, сдвигаем влево и уменьшаем порядок.
  • Нормализуем, округляем, проверяем особые случаи.

3.0 / 1.5 = 2.0 — точно.
1.0 / 3.0 = 0.010101…₂ — необходимо округление.

Дополнительно, 3 мин. Для normal значащие части в [1,2), их отношение в (0.5,2), поэтому достаточно одного сдвига влево до normal при допустимом порядке.

Близкие приближения: ошибка усиливается

Пусть x = 1.23456789, y = 1.23456780.

Истинная разность: 9 × 10−8.

Если каждый вход уже имеет абсолютную ошибку до 7.4 × 10−8, ошибка разности может достигать 1.48 × 10−7.
