С чего начать, если нет готовых библиотек и решений?

Но как исполнить нашу первую инструкцию?

S01 — условный идентификатор студента, 07 — значение оценки. Стрелка на слайде — смысловая связь, не машинная инструкция. На первой стадии выполняется только вывод одной строки; таблицу добавим дальше.

BIOS начинает загрузку

  1. После сброса CPU выбирает инструкции прошивки BIOS.
  2. BIOS выполняет начальную проверку и выбирает дискету.
  3. Читает её первый сектор по адресу 0000:7C00.
  4. Передаёт управление коду этого сектора.

BIOS не загружает весь журнал за один шаг.

8–10 мин. В QEMU PC выбираем boot order=a, образ дискеты имеет размер 1.44 MiB. BIOS размещает 512-байтный сектор по физическому адресу 0x7C00; на конце сектора стоит подпись 55 AA. Дальше исполняется наш NASM boot16.asm. Здесь нет GRUB, Multiboot или перехода в long mode.

AH и AL — половины одного AX. Копирование в ES не связывает регистры навсегда.

Первое знакомство с NASM. mov назначает значение регистру слева от запятой. 0x — запись шестнадцатеричного числа; 1000h обозначает то же число. После mov es,ax оба регистра имеют значение 1000h, но дальнейшее изменение AX не изменит ES. AH и AL — старший и младший байты AX; изменение одного меняет часть AX.

Что означает 1000:0000?

В real mode адрес записывают как сегмент:смещение.

ES:BX — куда BIOS положит данные; CS:IP — откуда CPU читает команды.

Оба компонента 16-битные, числа на схеме шестнадцатеричные. 16 десятичное = 10h. Пример: 0000:7C00 соответствует физическому 0x7C00. После чтения код попадает в RAM по ES:BX=1000:0000; после дальнего перехода CS:IP=1000:0000 указывает на те же байты уже как на инструкции. DS:SI позже укажет данные, SS:SP — стек.

Буфер начинается в ES:BX = 1000:0000; 17 секторов = 8704 байта.

BIOS заранее поместил сектор 1 в 0000:7C00. Наш загрузчик просит BIOS скопировать сектора 2–18 той же дорожки в последовательные байты RAM. 17×512=8704=0x2200, последний байт 0x10000+0x2200−1=0x121FF. Буфер — область RAM с загружаемой программой, не сектор на носителе и не будущий 512-байтовый буфер для сохранения оценок на отдельный HDD.

В загрузчике DL берём из значения, которое передал BIOS. 11h = 17 десятичное.

Эти квадраты — состояния регистров непосредственно перед INT 13h AH=02. AX составлен из AH:AL, CX из CH:CL, DX из DH:DL. DL=00h в текущем запуске с дискеты, а код сохраняет и восстанавливает именно номер загрузочного диска, переданный BIOS.

Вызов инициирует инструкция программы; IRQ клавиатуры придёт от устройства позже.

CPU кладёт на стек FLAGS, CS и IP следующей инструкции, затем получает адрес обработчика из IVT (для 13h четыре байта начиная с 0x004C). BIOS использует входные регистры, обращается к диску, возвращается через IRET. CF=1 сообщает ошибку; код проверяет и AL — сколько секторов прочитано. Путь данных дискета→RAM отличается от пути управления программа→BIOS→программа. Не путать программное INT 13h и аппаратный IRQ1, рассматриваемый в версии 4.

Наш сектор загружает оставшийся код

mov ax, 0x1000         ; выбрать сегмент 1000h
mov es, ax             ; ES = сегмент буфера в RAM
xor bx, bx             ; BX = 0, начало буфера
mov ah, 0x02           ; функция BIOS: читать сектора
mov al, 17             ; прочитать 17 секторов (2…18)
mov cl, 2              ; начать со второго сектора

jc boot_error          ; CF=1: ошибка чтения
jmp 0x1000:0x0000     ; исполнять код из RAM

Ключевые строки boot16.asm; CH, DH, DL и проверка AL есть в полном коде.

Это сокращённый фрагмент, не готовая программа: CH=0, DH=0, DL — номер диска, переданный BIOS. xor bx,bx обнуляет BX, а jc переходит только при установленном CF. Если CF=0, но AL не равно 17, полный код также выдаёт BOOT ERROR. Дальний jmp меняет CS:IP на 1000:0000; те же байты уже лежат там после чтения.

Сервис BIOS вызываем сами; это не IRQ от устройства.

AX=0E37h составлен из AH=0Eh и AL=37h. BIOS-видеосервис INT10 AH=0Eh берёт символ из AL и страницу из BH. BX=0007h задаёт BH=0 и BL=7; в текстовом режиме цвет уже определяет текущий атрибут, BL здесь не нужен. В реальном bios_text символ в AL поступает из строки, а не из отдельной команды mov al,'7'.

Сначала воспользуемся сервисом BIOS

Код версии 1: вывести всю запись

; SI указывает на строку «S01  grade 07»
.next:                   ; метка начала цикла
    lodsb                ; байт DS:SI → AL, SI += 1
    test al, al          ; проверить AL на нуль
    jz .done             ; нуль: конец строки
    mov ah, 0x0e         ; BIOS: вывести символ
    mov bx, 0x0007       ; BH=0: страница, BL=07h
    int 0x10             ; вывести AL через BIOS
    jmp .next            ; перейти к новому символу
.done:                   ; конец цикла

Символ ; начинает комментарий; .next: — метка. Строка заканчивается нулём.

Это внутренний цикл bios_text: SI указывает на ASCIIZ-строку S01 grade 07 в DS=CS. lodsb читает байт и продвигает SI, BIOS выводит символ, при нуле завершаем. В полном коде процедура также сохраняет AX/BX и заканчивается ret. C-эквивалент while (*p) putchar(*p++) — только объяснение алгоритма; исполняется NASM.

Код NASM: выделить 64 ячейки

grades: times 64 db 0xff  ; метка + 64 байта «нет оценки»
student: db 0             ; байт номера студента
work: db 0                ; байт номера работы

grades + 4 × student + work — адрес выбранной оценки.

db и times — директивы сборки; C-пояснение: uint8_t grade[16][4];

В stages/stage2/journal.asm директива times резервирует и инициализирует 64 байта. После старта отдельный цикл rep stosb снова задаёт UNSET — исходное состояние. Сегмент DS установлен равным CS, поэтому метка grades доступна через DS. В C это соответствовало бы двумерному массиву, но C не исполняется гостем. ES=B800h; DI=160×строка+2×столбец. Команда stosw записывает оба байта и увеличивает DI на 2.

В little-endian x86 слово AX=0F37h записывается по возрастанию адресов как 37 0F. Здесь DS:SI относится к исходной ASCII-строке, а ES:DI — к текстовому VGA. Например, для row=4, col=9 DI=658 десятичное=0292h, физический адрес B8292h. В полном vga_text DI вычисляется заранее; при выводе нескольких символов stosw продвигает его на два.

Ключевые инструкции процедуры vga_text.

Адрес текстовой видеопамяти получается через сегмент ES. Полный код vga_text содержит цикл до нулевого байта, вычисление DI и сохранение регистров. На слайде отмечена граница: это фрагмент, а не весь исполняемый файл. ASCII строки на экране выбраны латинскими, не обещаем Unicode.

Как BIOS найдёт сектор LBA 1?

dap: db 16, 0          ; размер пакета: 16 байтов
     dw 1              ; прочитать один сектор
     dw sector, 0x1000 ; буфер: сегмент 1000h,
                       ; смещение метки sector
     dq 1              ; LBA 1 (второй сектор)
mov si, dap            ; DS:SI → адрес пакета
mov dl, 0x80           ; первый HDD, не дискета
mov ah, 0x42           ; функция EDD «читать»

db/dw/dq задают 1/2/8-байтовые поля; для записи AH=43h.

DAP задаёт буфер offset:segment, поле здесь 1000:sector; это отдельный буфер для сохранения оценок, не прежний ES:BX=1000:0000 для загрузки программы. DS=1000 для пакета, BIOS использует адрес из DAP для данных. Один сектор 512 байт. INT13 Extensions AH=42/43 работают с LBA; CF при ошибке проверяется.

times 510 - ($ - $$) db 0 ; дополнить до байта 510

Это директивы сборки NASM, не команды CPU.
