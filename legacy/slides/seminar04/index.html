Бинарный сектор — не ELF для Linux

Исходникhello.asmbits 16, org 7C00h
→
Загрузочный сектор512 байтовПоследние два: 55 AA
→
RAM0000:7C00BIOS запускает CPU

Внутри: настройка DS/SS:SP → lodsb → INT 10h → конец строки.

./hello.bin в терминале Debian не запускает код real mode.

Из корня скопировать исходник cp -n demos/seminar04/hello.asm work/seminar04/hello.asm и войти в work/seminar04. Пройти код по инструкции: сегменты и стек, cld, ASCII-строка, BIOS AH=0Eh, завершающий нулевой байт. NASM times и dw формируют образ, не исполняются CPU.

Соберите сектор собственными командами

nasm -f bin hello.asm -o hello.bin
wc -c hello.bin
od -An -tx1 -j 510 -N 2 hello.bin
cp hello.bin hello.img
truncate -s 1440K hello.img

-f bin — плоский код; -o — выход. od: байты hex без адресов, пропустить 510, прочитать 2.

truncate доводит образ дискеты до 1440×1024 байтов.

Студенты сами видят через wc 512 байтов и через od 55 aa. ndisasm -b 16 hello.bin — дополнительный взгляд на первые инструкции. cp сначала копирует сектор, truncate дополняет образ до размера дискеты, не меняя начало. Попросить поменять строку, повторить nasm, cp и truncate, проверить новое сообщение.

Что означает запуск QEMU?

qemu-system-i386 -machine pc -m 16M -boot order=a \
  -drive file=hello.img,format=raw,if=floppy \
  -display gtk -no-reboot
-machine pc · -m 16MПК с 16 MiB RAM
-boot order=aзагрузить с дискеты
-drive … if=floppyRAW-образ дискетного привода
-display gtk · -no-rebootокно; не перезапускать гостя
После запуска увидеть HELLO BIOS. Длинная команда разбита обратным слешем: это одна команда shell. file= задаёт путь, format=raw говорит что нет заголовка qcow2, if=floppy подключает как дискету. -no-reboot относится к поведению QEMU после reset гостя, закрыть окно или Ctrl+C для выхода.

Два бинарных файла → одна дискета

nasm -f bin boot16.asm -o boot.bin
nasm -f bin journal.asm -o journal.bin
wc -c boot.bin journal.bin
dd if=/dev/zero of=boot.img bs=512 count=2880
dd if=boot.bin of=boot.img bs=512 conv=notrunc
dd if=journal.bin of=boot.img bs=512 seek=1 \
  conv=notrunc

Загрузчик — сектор 1. Журнал — следующие 17 секторов; предельную длину посчитайте.

Сначала cp -n boot16.asm и stages/stage6/journal.asm в work/seminar04, затем команды слайда из этого каталога. dd if=источник, of=цель, bs=512 bytes, count=2880 blocks; /dev/zero нулевой диск. seek=1 смещает запись журнала в выходном файле на 512 байтов. conv=notrunc сохраняет оставшуюся часть образа. При превышении 17*512 загрузчик не прочтёт всю программу.

Оценки — на другом диске

truncate -s 1M grades.img  # только перед первым запуском
qemu-system-i386 -machine pc -m 16M -boot order=a \
  -drive file=boot.img,format=raw,if=floppy \
  -drive file=grades.img,format=raw,if=ide,index=0,media=disk \
  -display gtk -serial stdio -monitor none -no-reboot

Первый -drive — код, второй — данные. -serial stdio показывает COM1 в терминале.

Проверьте 0, вправо, A, S → SAVED; повторный запуск → LOADED.

Не повторять truncate -s1M после сохранения: студенты должны оставить тот же grades.img при следующем QEMU-запуске. if=ide,index=0,media=disk подключает первый HDD BIOS DL=80h. monitor none отключает командную консоль QEMU; keyboard ввод через окно QEMU. После правки журнала повторить NASM и все три команды dd для чистой дискеты, не пересоздавая grades.img.

Таблица кодов на следующем слайде. После вычисления студент меняет константу AH и повторно собирает journal.bin, затем dd seek=1 в boot.img. Видеоячейка — два байта, AL ASCII, AH атрибут. Исходная очистка VGA mov ax,0720h действует на пробелы, не определяет цвет позднейших символов.

Заголовок: строка 2, столбец 5

В кодеredrawmov bx перед title_text
На экранестрока 2 · столбец 5отсчёт координат с нуля

BH — строка, BL — столбец.
BX = 256×строка + столбец.

Смещение VGA = 2×(80×строка + столбец) от B800:0000. Укажите физический адрес первой буквы.

В строке2 свободно между help row1 и headings row3. Только в заметках: BX=0205h; смещение 330=14Ah; физический адрес B814Ah. После правки пересобрать journal.bin и заново создать boot.img тремя командами dd; проверить, что надпись целиком помещается на строке.

Для каждого пункта: расчёт → команды → ожидание → наблюдение → объяснение.

Отчёт содержит расчёты атрибута, BX, адреса VGA, scan codes и LBA. Студент сам сравнивает значения с экраном, COM1 и байтами образа; код успешного автоматического теста не нужен. Наблюдение сохранения обязательно после нового запуска QEMU с тем же файлом HDD.

Домашняя работа: C и GDB

gcc -std=c11 -Wall -Wextra -Werror -g -O0 \
  ../../demos/seminar04/memory.c -o memory
./memory
gdb -q ./memory

break show_memory → run → x/4xb x → x/3dw numbers.

Виртуальные адреса программы Linux не являются адресами BIOS-журнала.

Из рабочего каталога путь к memory.c через ../... gcc -g добавляет отладочную информацию, -O0 отключает оптимизацию, -Wall/-Wextra/-Werror включают диагностику, -o задаёт имя. Студент вводит команды GDB вручную, а не запускает скрипт; увидит размеры1/4/8 и байты 78 56 34 12 в little-endian.

Ручной опыт с повреждённым сектором

cp -n grades-lab.img grades-corrupt.img
printf '\001' | dd of=grades-corrupt.img bs=1 \
  seek="$((OFFSET + 8))" conv=notrunc

OFFSET — ваше рассчитанное начало сектора. Меняется один байт оценки в новой копии; checksum остаётся прежним.

Запустите QEMU с копией: BAD_CHECKSUM не должен заменить текущие оценки.

До команды проверьте, что на первом байте оценки в сохранённом секторе находится 12, иначе новое значение 1 может совпасть со старым. Отдельное имя не даёт затронуть grades-lab.img. Студент наблюдает BAD_CHECKSUM после запуска, вводит новую оценку и пробует E: ошибочная загрузка оставляет её неизменной.
