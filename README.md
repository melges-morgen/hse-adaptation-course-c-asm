# Адаптационный курс к дисциплине «Алгоритмы и алгоритмические языки»

Репозиторий содержит методические материалы адаптационного курса для студентов первого курса факультета Программной инженерии НИУ ВШЭ.

Курс предназначен для выравнивания стартовой подготовки вчерашних школьников перед изучением дисциплины «Алгоритмы и алгоритмические языки», в которой используются язык C и ассемблер NASM.

## Содержание курса

Материалы охватывают:

- системы счисления;
- представление целых и вещественных чисел в памяти компьютера;
- базовые понятия архитектуры ЭВМ;
- основы операционных систем;
- Linux как рабочую среду программиста;
- инструменты сборки программ на C и NASM;
- основы Git;
- приложения со справочными материалами.

## Учёт успеваемости

Локальные ведомости и отчёты храните в `results/` по схеме
`семестр/группа/контроль`. Семестр обозначайте календарным годом и сезоном:
`YYYY-spring` или `YYYY-autumn` (например, `2026-spring`). Для каждого контроля
разделяйте исходные таблицы и сформированные результаты:

```text
results/
  2026-spring/
    БПИ264/
      КР-1/
        source/    # исходные ведомости и полученные отчёты студентов
        reports/   # обработанные ведомости, отчёты и сводки
```

Для других групп и контролей создавайте аналогичные папки в нужном семестре.
Здесь хранятся ведомости и полученные отчёты студентов; исходники программ
и остальные файлы работ в это хранилище не включаются.
Общие шаблоны контролей и генераторы остаются в `assessments/` и `scripts/`;
существующие файлы `groups/` автоматически сюда не переносятся.

Весь `results/` исключён из Git, включая вложенные папки и документы с ФИО
и оценками. Данные остаются только на вашем компьютере: при переносе репозитория
на другую машину скопируйте их отдельно.

Подробнее о структуре и использовании: [хранение ведомостей и отчётов](docs/student-results.md).

### Источники истины

Для подготовки новых занятий используйте `pud_adaptation_course.tex` как
актуальную программу раздела 2: именно там зафиксированы темы и результаты
обучения лекций и семинаров №4--8. Текст пособия берётся из
`adaptation_course.tex` и подключённых файлов под `tex/`, а редактируемым
источником презентации является `slides/lectureNN/index.html`.

`docs/superpowers/` хранит историю согласованных решений и планов. Каталог
`legacy/` предназначен только для исторической сверки и не является источником
текущего содержания. Каталог `examples/` содержит внешние образцы и не задаёт
требования курса.

## Сборка PDF

Локальная сборка выполняется только в Docker-контейнере. Устанавливать TeX Live или другое тяжёлое TeX-окружение в систему не требуется.

Для сборки PDF:

```bash
make pdf
```

Результат появится в каталоге:

```text
build/pdf/adaptation_course.pdf
```

### Практикум к первой контрольной

`test1_practice.tex` — отдельное пособие по лекциям и семинарам №1–3
(системы счисления, целые числа и числа с плавающей точкой). Оно включает:

- ссылки на основной материал лекций и семинаров №1–3 и необходимые обозначения;
- раздел «Примеры решений» с 10 пошаговыми разборами по занятиям №1–2;
- 32 самостоятельных задания по занятиям №1–2 в восьми тематических блоках;
- два тренировочных варианта: К1–К8 по занятиям №1–2 и В1–В8 по занятиям №1–3;
- краткие ответы, подробные решения, схемы самопроверки на 100 баллов
  и рекомендации по повторению.

Каждый вариант рассчитан на 90 минут (80 минут на решение и 10 на проверку)
и выполняется вручную без калькулятора. В варианте В1–В8 за темы занятий №1–2
предусмотрено 60 баллов, за `float32`, IEEE 754 и округление из занятия №3 — 40 баллов.

Разделы пособия находятся в `tex/practice/test1/` и используют общую преамбулу курса.
В PDF условия, ответы и решения связаны ссылками.
Теория изложена в основном пособии `adaptation_course.pdf`. Ссылки на него в практикуме
относительные: при передаче материалов размещайте оба PDF в одной папке.

Сборка через Docker:

```bash
make practice-pdf
```

Результат: `build/pdf/test1_practice.pdf`.

Для удаления артефактов сборки:

```bash
make clean
```

### Лекция и семинар №2: три артефакта

Занятие №2 охватывает кодирование графики, звука, текста, целых и вещественных
чисел, машинных команд, маски и сдвиги. Лекция и семинар рассчитаны на **90 минут
каждый**. В семинаре есть шесть обязательных тематических задач с отдельными
решениями, семь заданий для самостоятельной работы и дополнительные разборы.

Для каждой лекции используется схема: **развёрнутая глава пособия + Reveal.js +
PDF тех же слайдов**. Сейчас презентационные комплекты подготовлены для лекций №2, №3 и №4.

```bash
make lecture2          # пособие, HTML-презентация и PDF слайдов
make lecture2-slides   # только HTML и PDF слайдов
```

| Артефакт | Путь |
|---|---|
| Основное пособие с лекцией и семинаром | `build/pdf/adaptation_course.pdf` |
| Reveal.js-презентация | `build/html/lecture02/index.html` |
| PDF презентации | `build/pdf/lecture02/lecture02-slides.pdf` |
| Отчёт проверки вёрстки слайдов | `build/lecture02-check.json` |

Презентация содержит **52 основных слайда (включая источники) и 10 дополнительных**.
Подробная арифметика float идёт после итогов, отмечена «Дополнительно» и не входит
в 90 минут. Занятие №3 углубляет тему вычислений, округления и погрешностей.
Практикум к контрольной тренирует выбранные темы; графика, звук, Unicode и команды
отрабатываются в семинаре №2 основного пособия.

Исходный PPTX служит образцом оформления и тематической основой. Общая тема
`slides/theme/course.css` воспроизводит формат 16:9, тёмный титул с точечным
декором, светлую рамку обычных слайдов, тёмные округлые блоки, бирюзовые акценты
и типографику с Calibri-совместимым Carlito. Содержание презентации находится
в `slides/lecture02/index.html`; заметки преподавателя — в `aside.notes`.

Сборка выполняется в отдельном Docker-образе с Chromium для экспорта в PDF.
Reveal.js 5.2.1, Playwright 1.58.2 и зависимости закреплены lock-файлом;
версии пакетов шрифтов закреплены в `slides/Dockerfile`. Устанавливать Node.js,
браузер или шрифты на хост для сборки не нужно. Первая сборка требует интернета
для Docker и зависимостей; готовая презентация использует только локальные ресурсы.
Для передачи HTML копируйте **весь каталог `build/html/`**, включая `theme/`,
`vendor/` и подпапки `materials/` занятий. PDF находятся отдельно в `build/pdf/`.
У лекции №4 и семинара №4 рядом с PDF в папке занятия лежит копия
студенческих `materials/` с теми же файлами, что и в HTML-публикации.
Материалы преподавателя и готовые решения в публикацию не включаются.

### Комплекты для студентов

Папки `materials/` формируются как самостоятельные комплекты для выдачи архивом,
а не как копии дерева исходников `demos/` или `tex/`. Кладите только нужные
студенту файлы под короткими понятными именами; при совпадении имён разных
версий добавляйте говорящий суффикс, например `journal-stage3.asm`. В корне
каждого комплекта нужен `README.md` с назначением файлов и командами,
работающими после распаковки без исходного репозитория. Не включайте
преподавательские решения, внутренние скрипты проверки и временные файлы.
Проверяйте точный состав архива и практические команды на распакованной копии.

Обычный просмотр возможен открытием HTML-файла. Для режима преподавателя
используйте HTTP-сервер; например, при наличии Python:

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory build/html
```

Адрес: `http://127.0.0.1:8000/lecture02/`. Стрелки и пробел переключают слайды,
`Esc` открывает обзор, `S` — заметки преподавателя. На узком экране удобнее
альбомная ориентация. В PDF каждый слайд занимает одну страницу, фрагменты
раскрыты; заметки преподавателя в PDF не включаются.

Сборка проверяет загрузку ресурсов, отсутствие внешних запросов и переполнений
слайдов, наличие заметок, число и формат страниц PDF. Числовые примеры отдельно
проверяются командой `python3 scripts/check-lecture02.py`.

### Вариант `lecture02-original`: структура исходного PPTX

Вторая презентация сохраняет **60 слайдов, их темы и порядок** из исторического
исходника `legacy/sources/Лекция_2_Кодирование_данных_и_команд.pptx`. Слайды сделаны как редактируемый
HTML на той же общей теме, что и `lecture02`: текст, таблицы, формулы и схемы
можно править в исходнике. Формулировки уточнены, предметные ошибки исправлены.
Факультативная арифметика float остаётся на исходном месте — слайды **42–50**.

Это **действующая альтернативная презентация по лекции №2, которая уже была
фактически прочитана**. Она сохраняется в основном репозитории, собирается и
публикуется в CI наряду с основным сценарием лекции.

```bash
make lecture2-original
```

| Артефакт | Путь |
|---|---|
| Исходник | `slides/lecture02-original/index.html` |
| Reveal.js | `build/html/lecture02/original/index.html` |
| PDF (60 страниц) | `build/pdf/lecture02/lecture02-original.pdf` |

Атрибут `data-source-slide` у каждого слайда связывает его с номером слайда PPTX.
Сборка проверяет непрерывную последовательность 1…60. Это вариант по структуре
PPTX; основной `lecture02` остаётся отдельным сценарием на 90 минут.
После запуска HTTP-сервера из инструкции выше адрес нового варианта:
`http://127.0.0.1:8000/lecture02/original/`.

Оба варианта используют один экспортёр. Реестр `slides/presentations.json`
задаёт ожидаемое число слайдов, число основных слайдов и имя PDF.
Аргументы `slides/build.mjs` и `slides/check-artifacts.mjs`:
`[buildDir] [presentationId]`; по умолчанию — `build` и `lecture02`.
Исторический PPTX нужен только для редакторской сверки, а сборка работает с
HTML-исходником.

Полная сборка обоих вариантов и пособия:

```bash
make lecture2 lecture2-original
```

### Лекция №3: арифметика с плавающей точкой и погрешности

Продолжение IEEE 754 из лекции №2: **90 минут**, 38 основных слайдов
и 8 дополнительных. Сначала разбираются выравнивание порядков, GRS,

### Лекция №4: как устроен компьютер и где исполняется программа

Программа занятия задана в `pud_adaptation_course.tex`. Комплект включает
**90 минут, 55 основных и 8 дополнительных слайдов**, развёрнутый текст
в главе 2 и заметки преподавателя. Рассматриваются CPU, RAM, HDD/SSD, GPU/VRAM,
плата и периферия, шины и контроллеры, иерархия памяти, кэш, DMA и прерывания.
Фон-неймановская и гарвардская организация отделены от прав исполнения страниц.

Сквозной пример `a[1] += 5` показывает два потока: машинные инструкции через
L1I и данные через L1D, регистр и АЛУ. Показаны байты кода, состояния массива
и отложенная запись. Примеры используют Linux x86-64 LP64; условные адреса
и упрощения микроархитектуры явно обозначены.

```bash
make lecture4          # пособие + проверки + HTML/PDF, Docker
make lecture4-slides   # HTML и PDF слайдов, Docker
make lecture4-check    # расчёты Python + сборка/запуск C и NASM в Docker
```

Для расчётной проверки нужен Python 3 (только стандартная библиотека).
Демонстрация запускается в контейнере `linux/amd64`; на ARM требуется
поддержка эмуляции amd64 в Docker. Проверяются размеры, порядок байт,
адресные смещения, результат C/NASM, машинные байты и выравнивание структуры.
Она не измеряет кэш-промахи и аппаратные прерывания: на слайдах это модели.

| Артефакт | Путь |
|---|---|
| Текст лекции в пособии | `build/pdf/adaptation_course.pdf` |
| Reveal.js | `build/html/lecture04/index.html` |
| PDF (63 страницы) | `build/pdf/lecture04/lecture04-slides.pdf` |
| Студенческие дополнения | `build/html/lecture04/materials/README.md` |
| Те же дополнения рядом с PDF | `build/pdf/lecture04/materials/` |
| Проверка вёрстки | `build/lecture04-check.json` |

Исходники текста: `tex/lectures/lecture04_intro.tex` и
`tex/lectures/lecture04_memory_execution.tex`. Презентация:
`slides/lecture04/index.html`; схемы: `slides/lecture04/assets/`.
Демонстрация: `demos/lecture04/`. Семинар №4 остаётся отдельным материалом.
Для просмотра через HTTP используйте `/lecture04/` после запуска сервера
из инструкции выше. Для передачи копируйте весь `build/html/`.

### Лекция №4: архитектура и организация компьютера

Сквозной пример — разработка журнала оценок группы на работающей программе:
запуск → вывод одной оценки → таблица из 16 студентов и четырёх работ → ввод
через BIOS-клавиатуру и IRQ1 → средние → сохранение и загрузка. Комплект
содержит **76 основных и 8 дополнительных слайдов**: аппаратное ограничение
сменяется NASM-фрагментом и результатом в QEMU. C присутствует как пояснение
алгоритма, но не исполняется на учебной машине.

Демонстрация загружается в QEMU без гостевой ОС: BIOS читает первый сектор
виртуальной дискеты, загрузчик NASM читает остальную программу и передаёт ей
управление. Процессор остаётся в 16-битном real mode; GRUB и long mode не
требуются. Учебное оборудование: VGA, PS/2, PIC и отдельный IDE-диск с
RAW-образом. В слайдах отдельно объясняются DMA, USB, современный GPU и NVMe,
но они не выдаются за исполняемый код демо. Аппаратный контракт и клавиши
описаны в `demos/lecture04-journal/README.md`.
Шесть самостоятельных NASM-исходников лежат в
`demos/lecture04-journal/stages/stage1/` … `stage6/`; соседние версии удобно
сравнивать через `diff -u`. Команда `STAGE=N` выбирает исходник и пересобирает
его перед интерактивным запуском.

```bash
make lecture4-journal       # текст пособия, QEMU-проверки, HTML и PDF
make lecture4-journal-check # шесть версий и проверка ввода/диска в QEMU
make lecture4-journal-run   # интерактивно: http://localhost:6080/vnc.html
make lecture4-journal-run STAGE=3 # ввод через BIOS INT 16h
```

Интерактивный экран доступен через noVNC из Docker по локальному адресу;
данные сохраняются в `build/lecture04-journal/grades.img` между запусками.
Для показа в браузере запустите `make lecture4-journal-run` в отдельном
терминале и откройте указанный адрес. В проверках QEMU работает headless.

| Артефакт | Путь |
|---|---|
| Текст лекции в пособии | `build/pdf/adaptation_course.pdf` |
| Reveal.js | `build/html/lecture04/journal/index.html` |
| PDF (84 страницы) | `build/pdf/lecture04/lecture04-journal.pdf` |

Исходники: `tex/lectures/lecture04_journal.tex`,
`slides/lecture04-journal/index.html` и `demos/lecture04-journal/`.

## Семинар №4: практическое продолжение лекции

Студент выполняет и защищает **один из двух вариантов**: базовый на C
или усложнённый на NASM/BIOS. Оба включены в общее пособие и доступны
отдельными HTML и A4 PDF.

**Вариант 1 (базовый):** [исходник методички по факториалу](tex/seminars/seminar04_factorial_body.tex).
Студент создаёт каталог и исходник через nano и Vim, собирает программу с
предупреждениями и `-g -O0`, проверяет случаи 0–20, исследует ошибки в GDB
и перенаправляет `stdin`, `stdout`, `stderr`. Исходник для автоматической
проверки остаётся внутренним, в студенческий архив входит только `README.md`
и `input.txt`. Выпуски:
`build/html/seminar04/factorial/index.html`,
`build/pdf/seminar04/seminar04-factorial.pdf`, материалы — в соседней
папке `factorial/materials/` соответствующего формата.

**Вариант 2 (усложнённый):** [исходник методички по журналу](tex/seminars/seminar04_body.tex).
Рекомендуется Debian Linux актуальной версии на компьютере или в виртуальной
машине. Подойдёт и другой дистрибутив Linux, если доступны QEMU с графическим
окном, NASM, GCC, GDB, binutils, `file` и базовые файловые утилиты.
Команды установки в методичке приведены для Debian; при выборе другого
дистрибутива студент самостоятельно разбирается с его пакетами и настройкой:
преподаватели не могут изучить особенности каждого дистрибутива. Для опыта
с C/GDB нужна среда Linux x86-64. Если среда ещё не готова, семинар №4 можно
посвятить её установке; невыполненные в аудитории задания завершаются дома.
Студенты собирают односекторную BIOS-программу, затем полный журнал. В нём они
самостоятельно рассчитывают цвет и позицию VGA, скан-коды, среднее
и новый номер сектора сохранения. Дома разбирают память в C/GDB,
сопоставляют исполняемый ELF-файл с процессом Linux и проверяют
вычисления и дисковый образ. Студенты выполняют команды
сборки и проверяют результат сами. Из каждого TeX-исходника в Docker собираются
HTML, отдельный A4 PDF и текст выбранного варианта в общем пособии.
`tex/seminars/seminar04.tex` подключает оба фрагмента напрямую;
для сборки общего пособия используйте `make pdf`.

После распаковки студенческого архива из его папки:

```sh
mkdir -p work
cp -n hello.asm work/hello.asm
cd work
nasm -f bin hello.asm -o hello.bin
```

Полные команды создания образов, запуска QEMU и объяснение их флагов
есть в инструкции варианта 2. `make seminar4` служит только для Docker-сборки
и проверки обоих вариантов; студенты выполняют команды вручную. Рабочие файлы
`work/` исключены из Git, включая отдельный образ
`work/grades.img`.
Методичка варианта 2: `build/html/seminar04/index.html`, `build/pdf/seminar04/seminar04.pdf`
и раздел в `build/pdf/adaptation_course.pdf`.
Студенческий комплект: `build/html/seminar04/materials/` и
`build/pdf/seminar04/materials/`. В каждой папке лежат только `README.md`,
`hello.asm`, `boot16.asm`, `journal.asm`, `memory.c`, `memory.gdb`, без дерева
`demos/` и дополнительных файлов. В архиве `journal.asm` — шестая версия
лекционного журнала. Полная методичка расположена рядом с комплектом.
Старая презентация сохранена для исторической сверки в `legacy/slides/seminar04/`.

Для преподавателя подготовлены [методические ответы](tex/teacher/seminar04_guide_body.tex)
и [памятка для устной защиты](tex/teacher/seminar04_defense_body.tex):
краткий маршрут и расширенный банк вопросов по обоим вариантам.
`make seminar4-teacher` собирает HTML в `build/teacher/seminar04/`, а PDF —
в `build/pdf/teacher/seminar04/`;
эти материалы не включаются в студенческие комплекты.

## Лабораторная работа №5: Git и процессы

[Единый исходник методички](tex/seminars/seminar05_body.tex) используется в
общем пособии и отдельной HTML/PDF-версии. Сначала студенты создают локальный
Git-репозиторий, проверяют игнорирование и восстановление файлов, ветвление
и слияние, а также `clone`/`push`/`pull` через соседний bare-репозиторий.
Затем собирают `status_demo.c` и `isolation_demo.c`, исследуют `$?`, PID,
память родителя и потомка и фиксируют результат в Git. Лабораторная №5
завершает практические занятия; отдельной лекции или семинара №8 нет.

```sh
make seminar5
```

Результаты: `build/html/seminar05/index.html`,
`build/pdf/seminar05/seminar05.pdf` и глава общего пособия
`build/pdf/adaptation_course.pdf`. Плоские студенческие комплекты находятся
в `build/html/seminar05/materials/` и `build/pdf/seminar05/materials/`:
в каждом только `README.md` и два C-исходника. C-примеры проверяются в
Docker; рабочие исполняемые файлы и результаты запусков не публикуются.
Отчёт отправляют преподавателю в PDF или HTML к следующему дополнительному
занятию для сдачи; исходники и репозитории хранят отдельно для защиты.

## Дополнительные материалы: Debian, Ubuntu, лабораторная и отчёт

### Debian: установка и первое знакомство с терминалом

[Дополнительная лабораторная](tex/supplementary/debian_install_body.tex) предлагает выбрать один
маршрут: VirtualBox с Debian amd64 в Windows x86-64; установка Debian второй
системой на Windows x86-64 с UEFI; UTM с Debian arm64 на Mac Apple Silicon;
либо установка Debian рядом с macOS через установщик команды Debian Bananas
после проверки поддержки конкретной модели.
После установки во всех маршрутах создают рабочий каталог, ставят инструменты,
пишут и запускают `hello.c`. Проверяемый исходник в `reference/` не входит в
студенческую публикацию. Отчёт отправляют преподавателю в PDF или HTML,
сохраняя исходник отдельно.

```sh
make debian-install
```

Результаты: `build/html/debian-install/index.html`,
`build/pdf/debian-install/debian-install.pdf` и соответствующая глава в
`build/pdf/adaptation_course.pdf`. Самостоятельные HTML/PDF также публикуются
на GitHub Pages и в артефактах сборки.

Пошаговая методичка для компьютера с уже установленными Ubuntu и Windows:
выбор Ubuntu в GRUB 2, запуск терминала, каталоги, файлы и редактор nano.
Единый исходник — `tex/supplementary/ubuntu_terminal_body.tex`. В общем пособии
это самостоятельная часть «Дополнительные материалы» перед литературой.
Отдельные HTML и A4 PDF собираются в Docker:

```sh
make ubuntu-terminal
```

Результаты: `build/html/ubuntu-terminal/index.html`,
`build/pdf/ubuntu-terminal/ubuntu-terminal.pdf` и раздел в
`build/pdf/adaptation_course.pdf`. Команда `make pdf` также включает раздел
в общее пособие, но не собирает отдельные HTML и PDF. При публикации
методичка добавляется на GitHub Pages, в артефакты сборки и PDF релиза.

### Демонстрационная лабораторная и образец отчёта

Короткий опыт на C показывает путь «ожидание → неверный результат → GDB →
исправление → повторные проверки». Студенты могут сравнить собственное
оформление с заполненным образцом: исходники
`tex/supplementary/lab_report_body.tex` и `tex/supplementary/lab_report_example_body.tex`.
Отчёты по лабораторным **отправляют преподавателю в PDF или HTML**;
исходники хранят отдельно для демонстрации. Собрать отдельные версии и
общий PDF через Docker:

```sh
make lab-report
```

Результаты: `build/html/lab-report/index.html`,
`build/html/lab-report/report.html`, `build/pdf/lab-report/demo-lab.pdf`,
`build/pdf/lab-report/example-report.pdf` и разделы в общем
`build/pdf/adaptation_course.pdf`. Проверяемые C-исходники находятся внутри
`supplementary/lab-report/reference/` и не публикуются отдельным студенческим
комплектом. Команда `make pdf` включает оба текста в общее пособие.

## GitHub Actions

В репозитории настроен workflow `.github/workflows/build-pdf.yml`.

Он:

- собирает Docker-образ;
- проверяет расчёты и запускает `make lecture2 lecture2-original lecture3 lecture4 lecture4-journal seminar4 ubuntu-terminal lab-report debian-install` (QEMU-проверки лекционной демонстрации не проверяют работы студентов);
- публикует пособие, PDF лекций, методичку семинара и общий ZIP HTML как artifact;
- при сборке ветки `master` размещает эти материалы в GitHub Pages;
- при публикации GitHub Release прикрепляет PDF, архивы исходников занятий и общий ZIP HTML.

Для регулярных сборок имя artifact содержит номер сборки, дату-время в UTC и короткий SHA коммита:

```text
adaptation-course-master-build-<run_number>-<YYYYMMDD-HHMMSSZ>-<short_sha>
```

PDF внутри каталога `pdf/` загружаемого artifact называется аналогично:

```text
adaptation_course-master-build-<run_number>-<YYYYMMDD-HHMMSSZ>-<short_sha>.pdf
```

Для GitHub Pages публикуется актуальная версия:

```text
pdf/adaptation_course.pdf
```

Для релизов версия берётся из тега релиза, например:

```text
adaptation_course-v1.0.0.pdf
```
