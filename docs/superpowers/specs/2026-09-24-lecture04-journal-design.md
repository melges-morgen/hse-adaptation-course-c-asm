# Лекция №4: журнал оценок без ОС — альтернативный сценарий

> Историческая спецификация x86-64. Действующий вариант утверждён в
> `2026-09-26-lecture04-real-mode-design.md` (16-битный NASM/BIOS).

ПУД раздела 2 задаёт тему архитектуры; основной комплект `lecture04` остаётся
действующим. Второй комплект рассказывает ту же тему через разработку журнала
на эмулированной x86-64 машине без гостевой ОС. 90 минут; HTML Reveal.js и PDF
из одного исходника; альтернативный текст пособия, не замена основной лекции.

## Аппаратный контракт

QEMU `pc` (i440FX), 64 MiB RAM, GRUB Multiboot2 с ISO, 64-битный стартовый код NASM,
ядро freestanding C; VGA text memory `0xB8000`, PS/2 (контроллер i8042), COM1
для автоматизированной проверки; PIC/IRQ1 после стадии опроса клавиатуры
(таймер обсуждается, IRQ0 остаётся замаскирован);
отдельный IDE RAW-накопитель, сектор LBA 1 читается/пишется через ATA PIO.
Загрузчик и BIOS являются стартовой инфраструктурой, а не гостевой ОС.
Портативность к иным контроллерам не предполагается. QEMU-образ 64 MiB RAM,
диск 1 MiB; файлы диска/ISO генерируются, не хранятся в Git.

Контрольные версии 1–6: экран, таблица из 16 ID и 4 оценок, опрос клавиатуры,
IRQ1 и очередь клавиш, подсчёт средних, сохранение/восстановление. Допустимые
оценки 0..10; `0xFF` — нет оценки; среднее двух знаков — целочисленное
округление до сотой по правилу half-up. Ввод действует по нажатию: цифры
0..9, `A`=10, стрелки двигают выбор, `Backspace` очищает, `S` сохраняет,
`L` загружает. Enter/Escape не нужны.
Сохранение — ровно один сектор с magic/version/размерами/64 оценками и
контрольной суммой, сериализован вручную. Повреждение оставляет RAM без
изменений. Отключённый диск даёт диагностическое сообщение.

Интерактивная демонстрация запускается в QEMU с графическим окном. Для
автоматической проверки QEMU работает headless: монитор посылает `sendkey`,
serial сообщает о событиях. Между запусками RAW-диск сохраняется; отдельно
проверяются сброс и восстановление, повреждённый и неподходящий форматы.
DMA и современные USB/PCIe/NVMe/GPU объясняются схемами как альтернативы
учебному PS/2/VGA/PIO, не выдаются за реализованный код. Реальный кэш
эмулятором не измеряется.

## Изложение

0–6 обзор ПК и условия; 6–18 старт и экран; 18–30 таблица; 30–44
polling→IRQ; 44–58 CPU, кэш, средние; 58–64 стек и память; 64–80 диск;
80–87 современный ПК, GPU и ОС; 87–90 итоги. На каждом шаге потребность,
вопрос, теория, решение и наблюдаемый результат. Схемы для CPU/RAM/шины,
пути инструкций и данных, IRQ, диска и иерархии памяти. PDF самодостаточен.

## Проверка

Docker QEMU smoke для каждой стадии; интерактивные тесты ввода и оценки 0/10,
среднего, исправления и очистки; порча и несовместимая версия; сохранение и
перезапуск. `make pdf`, сборка HTML/PDF с проверками ресурсов, заметок, числа
страниц, границ и визуальный просмотр. Действующая лекция 4 не меняет сценарий.
