# Инструкция по работе с Linux в виртуальной машине

## Почему мы будем работать именно с Linux

Учебные курсы строятся таким образом, чтоб готовить студентов к решению практических задач на работе. Неотъемлемой частью любой сферы программирования будет Linux – будь то непосредственно разработка под это семейство ОС, работа на удаленных серверах, настройка пайплайнов непрерывной интеграции или администрирование сетей. Дело в том, что Linux предлагает очень мощный терминал, прозрачность и универсальность терминальных команд, встроенную документацию на большинство команд и функций, удобный для изучения и работы формат исполняемых файлов.

Поэтому каждый разработчик должен иметь базовые представления о работе с операционными системами на ядре Linux. Эта инструкция поможет вам сделать первые шаги в работе с Linux.

## Виртуальная машина или установка второй системой

У большинства из вас на ноутбуках уже стоит Windows. Отказываться от нее насовсем сейчас означает потерять привычное удобство использования своего компьютера. В темпах нашего обучения это приведет к тому, что вы не сможете пользоваться ноутбуком для решения задач по учебе, поэтому такой вариант нам не подходит. 

Вообще, Linux – это только ядро операционной системы. Конкретных операционных систем, основанных на ядре Linux невероятно много – начиная от Android, заканчивая шуточной AMogOS, вдохновленной игрой Among Us. В этом курсе мы остановимся на Debian, как на популярной, гибкой в настройке и одновременно простой для новичков операционной системе на ядре Linux.

Мы предлагаем два варианта установки:

- Установить Debian как виртуальную машину  
- Установить Debian второй системой. 

Давайте разберем, что такое виртуальная машина, обсудим плюсы и минусы каждого подхода.

**Виртуальная машина**  – это программа-эмулятор, которая создаёт внутри вашего компьютера «ещё один компьютер»: с собственным виртуальным диском, оперативной памятью и виртуальным процессором. Внутри этого виртуального компьютера можно установить операционную систему – например, Debian – и работать с ней как с обычным компьютером, в отдельном окне.

Особенности виртуальной машины:

1. Виртуальная машина работает поверх вашей основной операционной системы (Windows, macOS или другой Linux) с помощью специальной программы –  гипервизора (например, VirtualBox или VMware).  
2. Всё, что происходит внутри ВМ, изолировано от основной системы: файлы, программы и настройки виртуального Debian не пересекаются с вашими личными файлами на хост-системе.  
3. ВМ хранится как один или несколько файлов на диске (виртуальный диск). Её можно удалить, скопировать или откатить назад – например, к «чистому» состоянию сразу после установки – без каких-либо последствий для основного компьютера.

Другой вариант – **установка второй системой**. Это означает, что на вашем компьютере будет две операционные системы. При запуске компьютера вам будет даваться выбор – какую систему загрузить. Установка ОС сама по себе немного сложнее, чем настройка виртуальной машины, а без должного опыта все очень быстро может пойти не так. В худшем случае все может закончится тем, что вы случайно затрете основную ОС и останетесь без ноутбука на какое-то время. Более того, даже если установка пройдет успешно, во время пользования второй ОС, вы можете случайно что-то испортить, “выстрелить себе в ногу”, что приведет к необходимости переустановки ОС. Но у подхода есть и плюсы: более «настоящий» опыт работы с Linux и отсутствие накладных расходов на гипервизор. 

Исходя из доводов выше, виртуальная машина – рекомендуемый способ начать работу с Linux для этого курса.

## Установка Debian в виртуальной машине

### 4.1. Выбор гипервизора

Рекомендуется **VirtualBox** – бесплатный, кроссплатформенный (Windows/macOS/Linux), с простым графическим интерфейсом. Альтернативы: VMware Workstation Player (Windows/Linux), UTM (macOS, особенно на процессорах Apple Silicon).

Скачайте и установите VirtualBox с официального сайта для вашей ОС.

### 4.2. Скачивание образа Debian

Скачайте **netinst-образ** (небольшой установочный ISO, который довыкачивает пакеты из интернета в процессе установки) для архитектуры **amd64** с официального сайта Debian (раздел загрузки, [debian-13.6.0-amd64-netinst.iso](https://cdimage.debian.org/debian-cd/current/amd64/iso-cd/debian-13.6.0-amd64-netinst.iso)). https://cdimage.debian.org/debian-cd/current/amd64/iso-cd/

### 4.3. Создание виртуальной машины

1. Откройте VirtualBox  **New (Создать)**.  
2. Укажите имя (например, `debian-course`), тип **Linux**, версия **Debian (64-bit)**.  
3. Выделите память: **не менее 2048 МБ** (рекомендуется 4096 МБ, если позволяет основной компьютер).  
4. Создайте новый виртуальный жёсткий диск, формат VDI, динамический, размер **не менее 20 ГБ**.  
5. В настройках созданной ВМ откройте **Storage (Носители)** и подключите скачанный `.iso` как оптический диск.  
6. Убедитесь, что в настройках System включена поддержка **PAE/NX** и, если доступно на вашем процессоре, **вложенная виртуализация (VT-x/AMD-V)**.

### 4.4. Установка Debian

1. Запустите ВМ — начнётся загрузка с ISO.  
2. Выберите **Graphical install** (графическая установка — проще для новичка).  
3. Пройдите стандартные шаги: язык, раскладка клавиатуры, имя компьютера, имя пользователя и пароль (запомните их — они понадобятся для `sudo`), разметку диска — выберите вариант **«Использовать всё пространство диска» (guided — use entire disk)**, единый раздел.  
4. На шаге выбора ПО (**tasksel**) достаточно оставить только **«standard system utilities»** — окружение рабочего стола не обязательно, но при желании можно добавить **«Debian desktop environment»**, если хочется графической оболочки. Для целей курса хватает системы без графической оболочки — вся работа будет вестись в терминале.  
5. Установите **GRUB** на основной диск, когда предложит установщик.  
6. Дождитесь завершения установки и перезагрузите ВМ (при перезагрузке отключите ISO-образ из виртуального привода, если система предложит).

### 4.5. Первый вход

После перезагрузки вы увидите приглашение на вход (login). Введите имя пользователя и пароль, заданные при установке — вы окажетесь в командной строке (если ставили систему без графической оболочки) или на рабочем столе, где нужно будет открыть приложение «Терминал» (Terminal, Konsole, xterm — в зависимости от окружения).

**Совет:** сразу после первой успешной загрузки сделайте **снапшот** ВМ (Snapshots → Take) — это «точка сохранения», к которой всегда можно будет вернуться, если что-то сломается в дальнейших экспериментах.

## 5\. Первые шаги в терминале

Терминал – очень мощный инструмент. На самом деле, графическая оболочка в Linux-based системах нужна в основном для удобства пользователей, не знакомых с терминалом на должном уровне. Компьютером полностью можно управлять через терминал и зачастую это намного быстрее и удобнее, чем через графическую оболочку.

Откройте терминал. Вы увидите приглашение вида:  
student@debian-course:\~\$

Это значит: пользователь student, компьютер debian-course, вы находитесь в своём домашнем каталоге (\`\~\` это сокращение для \`/home/student/\`). Фраза “вы находитесь” очень важна. Терминал всегда открыт в какой-то директории. От текущей директории зависят относительные пути до програм, файлы в каталоге и т.д. По умолчанию все запускаемые программы выполняются в текущей директории: ls покажет список файлов в текущей директории, touch создаст файл в текущей директории и т.д.

### 5.1. Создание рабочего каталога

Создайте отдельный каталог для работы на курсе и перейдите в него:

mkdir \-p \~/course  
ls  
cd \~/course  
pwd

`mkdir -p (make directory) –`  создаeт каталог (флаг `-p` не выдаёт ошибку, если каталог уже существует, и создает промежуточные каталоги при необходимости)

ls (list) – покажет список файлов и каталогов в текущей директории 

`cd` (change directory) – переходит в каталог который вы укажете, теперь терминал открыт в другой директории

`pwd` (print working directory) – печатает текущий путь: убедитесь, что вы действительно находитесь в `~/course`, прежде чем продолжать.

## 6\. Установка инструментов разработки

Нам нужно установить программы, которые мы будем использовать для разработки. В Linux-системах почти все можно установить одной командой из терминала. Давайте разберем на примере.

Прежде чем ставить пакеты, обновите список доступных пакетов из репозиториев Debian:

sudo apt update

sudo (super-user do) выполняет команду от имени администратора (root) — большинство операций с системными пакетами требуют повышенных прав. Система запросит пароль, который вы вводили при установке (при вводе пароля символы на экране не отображаются – это нормально, просто введите пароль и нажмите enter).

Установите набор инструментов, необходимый для сборки программ на C и ассемблере:

sudo apt install build-essential gcc make gdb nasm binutils

Что сюда входит:

* `build-essential` – метапакет с базовыми инструментами сборки (включает `gcc`, `make`, стандартные библиотеки для компиляции);  
* `gcc` – компилятор C;  
* `make` –- утилита автоматической сборки по правилам из `Makefile`;  
* `gdb` – отладчик;  
* `nasm` – ассемблер синтаксиса Intel;  
* `binutils` – набор низкоуровневых утилит, включая линковщик `ld`.

На запрос подтверждения установки (`Продолжить? [Y/n]`) нажмите `Y` и Enter (либо просто Enter — `Y` обычно выбран по умолчанию).

### 6.1. Проверка версий

После установки убедитесь, что инструменты действительно доступны и определите их версии:

gcc \--version  
nasm \-v  
ld \--version  
make \--version  
gdb \--version

Если каждая команда выводит номер версии — всё установлено верно. Если вместо этого вы видите ошибку — смотрите раздел 9 «Типичные ошибки».

## 7\. Первая программа на C

Давайте напишем и запустим первую программу на С. Ничего, если вы не знакомы с этим языком. Мы подскажем, что делать.

Создайте файл `hello.c` в рабочем каталоге. Проще всего сделать это с помощью консольного текстового редактора `nano`, доступного в Debian «из коробки»:

nano hello.c

Введите следующий код:

\#include \<stdio.h\>

int main(void) {  
    printf("Hello from C\!\\n");  
    return 0;  
}

Будьте внимательны с точками запятой, не перепутайте двойные кавычки и одинарные (нужны двойные). Проверьте, что ваша программа в точность соответствует примеру. 

Сохраните файл (`Ctrl+O`, затем Enter) и выйдите из редактора (`Ctrl+X`) – значения этих  и других команд написаны снизу.

### 7.1. Компиляция

После выхода из редактора, в той же директории запустите команду: 

gcc \-Wall \-o hello\_c hello.c

Это запуск компилятора gcc с флагами. Разбор флагов: `-Wall` включает предупреждения компилятора (полезно для учебных целей – стоит обращать на них внимание), `-o hello_c` задаёт имя итогового исполняемого файла, hello.c – наш файл с исходным кодом.

Наверняка многие из вас имеют опыт программирования и привыкли к запуску программы нажатием кнопки “play” в вашей любимой IDE. Согласен, что это удобнее, чем вводить команду в терминале. Однако настоящий профессионал должен понимать, что происходит при нажатии такой кнопочки под капотом, чтоб суметь сконфигурировать флаги, прочитать и исправить ошибки.

### 7.2. Запуск

./hello\_c

Обратите внимание на `./` перед именем файла — это явное указание «выполнить файл из текущего каталога».

Вы должны увидеть на экране:

Hello from C\!

### 7.3. Проверка кода завершения

Любая программа при завершении возвращает **код завершения** (exit code) — число от 0 до 255, где `0` традиционно означает «успех». Проверить код завершения последней команды можно так:

echo \$?

После успешного запуска `hello_c` вы должны увидеть `0` — это соответствует `return 0;` в коде программы.

## 8\. Типичные ошибки и как их читать

При первых попытках работы в терминале почти неизбежно встретятся типовые ошибки. Ниже – как их распознать и исправить.

### 8.1. command not found

\$ gccc hello.c  
bash: gccc: command not found

**Причина:** опечатка в имени команды, либо программа действительно не установлена. Проверьте написание, при необходимости установите пакет через `sudo apt install ...` (раздел 6).

### 8.2. Permission denied

\$ ./hello\_c  
bash: ./hello\_c: Permission denied

**Причина:** у файла нет права на выполнение. Проверить права можно командой `ls -l hello_c – вы увидите список из букв, в нем должна быть буква x (eXecute permission). Если ее нет – значит действительно нет права на исполнение,` вдать его можно командой:

chmod \+x hello\_c

Такая ошибка также встречается, если вы пытаетесь писать в системный каталог без `sudo`, либо запускаете скрипт, у которого не выставлен бит исполнения.

### 8.3. No such file or directory

\$ gcc \-o hello\_c hello\_c.c  
gcc: error: hello\_c.c: No such file or directory

**Причина:** указан неверный путь или имя файла — файла с таким именем нет в текущем каталоге. Проверьте содержимое каталога командой `ls` и текущее местоположение командой `pwd`; при необходимости перейдите в нужный каталог через `cd`.

### 8.4. Забытый ./

\$ hello\_c  
bash: hello\_c: command not found

**Причина:** в Linux текущий каталог по умолчанию **не входит** в `PATH` (список каталогов, где система ищет команды) — это сделано намеренно, из соображений безопасности, чтобы случайный файл в текущей папке не подменил системную команду. Поэтому файлы из текущего каталога нужно запускать с явным указанием пути:

./hello\_c

### 8.5. Неверный каталог

\$ ls  
ls: cannot access 'hello.c': No such file or directory

Если вы «потерялись» и не уверены, где находитесь и что доступно рядом — восстановиться и найтись помогают три команды:

pwd     \# где я нахожусь  
ls \-la  \# что есть в этом каталоге  
cd \~/course   \# вернуться в рабочий каталог курса

### 8.6. Ошибка компиляции (C)

\$ gcc \-Wall \-o hello\_c hello.c  
hello.c: In function 'main':  
hello.c:4:5: error: expected ';' before 'return'  
    4 |     printf("Hello from C\!\\n")  
      |                                             ^  
      |                                             ;  
    5 |     return 0;

**Как читать:** компилятор указывает файл (`hello.c`), строку и столбец (`4:5`), тип сообщения (`error`) и краткое описание. Здесь не хватает точки с запятой после вызова `printf`. Открывайте файл в `nano`, переходите к указанной строке и исправляйте. Важно: в силу особенностей работы компилятора строка и столбец бывают неточными. Часто имеет смысл посмотреть на код вокруг указанного места – может быть ошибка где\-то там. Не стоит бояться ошибок компиляции, их стоит уметь читать – часто все необходимое для решения проблемы уже есть в тексте ошибки.
