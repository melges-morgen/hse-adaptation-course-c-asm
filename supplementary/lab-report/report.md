# Пример отчёта: сумма двух чисел

**Это образец заполнения, а не файл для сдачи.** Автор, группа и дата ниже вымышлены. Свою лабораторную работу оформляйте по наблюдениям на собственном компьютере; отправляйте преподавателю отчёт в **PDF или HTML**, а исходные файлы сохраняйте отдельно для защиты.

**Автор:** Иванов Иван (условный пример).\
**Группа:** учебная группа ПИ-000 (условный пример).\
**Дата:** 1 октября 2026 года (условный пример).\
**Тема:** проверка суммы двух чисел и исправление логической ошибки.

## Цель и условия

Создать программу на C, вычисляющую сумму двух целых чисел. Перед запуском предсказать результат, сравнить его с выводом, исследовать причину расхождения в GDB и проверить исправление. Исходные данные: `a = 7`, `b = 5`. Ожидаемый результат: **`7 + 5 = 12`**.

## Среда и исходный файл

Для воспроизведения использовалась среда Linux (Debian 12), GCC 12.2 и GDB 13.1 с параметрами `-g -O0`. Я создал каталог `~/aiya/demo-sum` и набрал `sum.c` в редакторе nano. Исходная ключевая строка была:

```c
int result = a - b;
```

Остальной код выводил результат через `printf("Сумма: %d\n", result);` и возвращал `0` из `main`. Полный исходник до исправления показан в демонстрационной лабораторной; файл программы я сохранил отдельно от отчёта.

## Первый запуск и расхождение

Из рабочего каталога я выполнил:

```sh
gcc -std=c11 -Wall -Wextra -g -O0 sum.c -o sum
./sum
echo $?
```

GCC завершил сборку без предупреждений. Программа напечатала **`Сумма: 2`**; следующий `echo $?` показал `0`. До запуска я ожидал `Сумма: 12`. Следовательно, программа завершилась успешно с точки зрения её собственного кода возврата, но вычислила **не ту операцию**. Отсутствие предупреждений компилятора не означает, что логика задачи верна.

## Отладка

Я запустил `gdb -q ./sum` и ввёл команды в приглашении `(gdb)`:

```text
break sum.c:7
run
print a
print b
next
print result
quit
```

Остановка была **перед** вычислением `result`. Наблюдения: `print a` → `7`, `print b` → `5`; после `next` команда `print result` → `2`. Числа в обозначениях ответов GDB (`$1`, `$2` и т. п.) относятся к истории отладчика и не являются адресами переменных. В исходнике стояло вычитание вместо требуемого сложения; проблема не была связана с вводом данных или сборкой.

## Исправление и повторная проверка

Исправил ровно одну строку и **пересобрал** программу:

```c
// было: int result = a - b;
int result = a + b;
```

Для каждой дополнительной пары менял `a` и `b` в `sum.c`, снова выполнял указанную выше команду GCC и запускал `./sum`. Получил:

| `a` | `b` | Ожидалось | Наблюдалось | Код завершения |
|---:|---:|---|---|---:|
| 7 | 5 | `Сумма: 12` | `Сумма: 12` | 0 |
| 0 | 5 | `Сумма: 5` | `Сумма: 5` | 0 |
| -3 | 5 | `Сумма: 2` | `Сумма: 2` | 0 |

В конце вернул значения `a = 7`, `b = 5` и снова собрал программу. Файл `sum.c` и исполняемый файл `sum` сохранил для повторного показа.

## Вывод

Сравнение с заранее записанным ожиданием помогло обнаружить ошибку, которую GCC не распознал: программа вычитала `b` из `a` вместо сложения. Просмотр переменных и выполнение строки в GDB подтвердили причину результата `2`. После исправления и пересборки все три контрольные проверки совпали с ожидаемыми значениями. При подготовке собственного отчёта важно записывать **и неудачную попытку**, и подтверждение исправления — с командами и наблюдениями.
