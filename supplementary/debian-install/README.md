# Установка Debian и знакомство с терминалом

Это дополнительная лабораторная работа по подготовке собственной Linux-среды. Она основана на черновой инструкции из курса, но маршруты установки и терминальная практика здесь разделены. **Выполните только один маршрут**, подходящий вашему компьютеру, затем общее задание в терминале. Установка Debian в ВМ не заменяет уже установленную Windows или macOS; установка второй системой предусмотрена здесь только для **Windows x86-64 с UEFI**. На Mac с Apple Silicon мы используем **Debian arm64 в UTM**, а не установку второй системой.

Работа с Debian нужна для знакомства с файловой системой, компилятором и запуском программ Linux. Это отдельная подготовительная работа, а не третий обязательный вариант семинара №4. Если подходящая Linux-среда уже есть, можете сразу перейти к общей терминальной части и описать в отчёте существующую установку.

## Порядок сдачи дополнительной лабораторной по Debian

1. **На занятии** выполните доступную часть работы, зафиксируйте команды и наблюдения и покажите их преподавателю. Это промежуточный показ.
2. **К следующей лабораторной** завершите выбранный маршрут и практику, подготовьте отчёт: выбранный способ установки и причина выбора, команды, ожидаемый и фактический результаты, трудности и их решение. **Отправьте преподавателю отчёт в формате PDF или HTML.** Сохраните исходник `hello.c` отдельно для демонстрации; не включайте в отчёт пароли и ключи восстановления.
3. **В начале следующей лабораторной** пройдите короткий тест по базовой теории предыдущей работы. Тест обязателен, но его результат не является допуском к устной защите.
4. **Во время следующей лабораторной** индивидуально защитите работу: покажите отправленный отчёт, рабочую систему и исходник, повторите сборку и запуск, ответьте на вопросы. Преподаватель сообщит, что нужно исправить.
5. **Последняя лабораторная** выполняется, показывается и защищается на том же занятии. В его начале проходит тест по предпоследней работе; отдельного следующего теста по последней работе не будет.

Образец оформления собственного отчёта ищите рядом, в дополнительном материале «Пример отчёта: сумма двух чисел». Его наблюдения относятся к другой программе — замените их своими.

## Выберите маршрут: плюсы и минусы

**Хост** — уже работающая Windows или macOS; **гость** — установленный внутри виртуальной машины Debian. На Windows x86-64 рекомендую начать с VirtualBox: его диск легко отличить от диска Windows. Если нужно запускать Debian непосредственно на оборудовании, подойдёт установка второй системой при заранее подготовленном свободном месте. На Mac с Apple Silicon используйте UTM с ARM-версией Debian.

| Подход | Плюсы | Минусы и границы |
|---|---|---|
| Windows: ВМ VirtualBox | Windows и Debian доступны одновременно; диск ВМ можно копировать и восстанавливать. | Требуются ОЗУ и место на диске хоста; доступ к устройствам ограничен. |
| Windows: вторая ОС | Нативная скорость и прямой доступ к оборудованию. | Переключение через перезагрузку; разметка и загрузка затрагивают реальный диск. |
| Mac: ВМ UTM | Быстрая arm64-виртуализация; macOS остаётся доступной. | Это не Linux x86-64: задания NASM/x86 требуют другой среды. |

Всем маршрутам нужна сеть при установке из **netinst ISO**: установщик скачивает недостающие пакеты. Названия пунктов интерфейса могут немного отличаться в разных выпусках. Скачивайте *актуальный стабильный выпуск*, не привязываясь к номеру ISO из черновика: на [официальной странице Debian netinst](https://www.debian.org/distrib/netinst) выберите **amd64** для Windows-ПК или **arm64** для Mac Apple Silicon. Эти ISO не взаимозаменяемы. Перед использованием сравните контрольную сумму SHA256 скачанного файла с файлом `SHA256SUMS` в том же официальном каталоге (в Windows можно применить `Get-FileHash`, в macOS — `shasum -a 256`).

## Маршрут А. Debian в VirtualBox на Windows

1. Установите [VirtualBox с официального сайта](https://www.virtualbox.org/wiki/Downloads) в Windows. Если VirtualBox сообщает о недоступности аппаратной виртуализации, проверьте, включены ли **Intel VT-x / AMD-V** в настройках компьютера. Это возможность *хоста*, не «вложенная виртуализация» внутри ВМ. Не меняйте параметры системы наугад: при затруднении обратитесь к инструкции производителя.
2. Скачайте Debian **amd64 netinst**. В VirtualBox нажмите **New / Создать**, назовите машину `debian-course`, выберите ISO и систему **Debian (64-bit)**. Если мастер предлагает автоматическую установку, включите **Skip Unattended Installation / Пропустить автоматическую установку**, чтобы пройти учебные шаги вручную.
3. Выделите примерно **2 процессорных ядра** и **4096 МБ ОЗУ** (при меньшем объёме памяти компьютера допустимы 2048 МБ и лёгкое графическое окружение). Не выделяйте гостю всю память хоста. Создайте **новый динамический виртуальный диск** размером не меньше **30 ГБ**; убедитесь, что выбран именно новый диск ВМ, а не существующий файл с вашими данными.
4. Запустите ВМ с ISO и выберите **Graphical install**. Задайте язык, раскладку, имя компьютера `debian-course` и обычного пользователя. Если установщик предлагает пароль отдельного пользователя `root`, оставьте его пустым: согласно документации Debian первый обычный пользователь тогда получает возможность применять `sudo`. Не используйте пароль из примеров курса.
5. На этапе разметки выбирайте «Использовать весь диск» **только после проверки**, что в списке указан **виртуальный диск ВМ** (его размер должен совпадать с созданным вами, около 30 ГБ). Подойдёт один основной раздел для начинающего пользователя. Перед окончательным подтверждением прочитайте перечень действий установщика.
6. При выборе программ оставьте **standard system utilities** и выберите рабочий стол Debian (например, GNOME; на слабой ВМ можно выбрать Xfce). Установите GRUB на **диск ВМ**. Дождитесь завершения, отключите ISO от виртуального привода, если установщик предлагает это сделать, и перезагрузите ВМ. Войдите под созданным пользователем. После первой успешной загрузки можно сделать снимок ВМ через меню VirtualBox **Snapshots**.

Диск ВМ — это файл на Windows-компьютере; выбор «весь диск» в этом маршруте **не относится к диску Windows**. Если не уверены, какой диск показывает установщик, вернитесь к настройкам ВМ до подтверждения разметки.

## Маршрут Б. Windows x86-64 с UEFI: Debian второй системой

Это работа с **реальным диском компьютера**. Прежде чем запускать установщик, сохраните резервную копию важных файлов Windows на другом носителе. В Windows проверьте через `msinfo32`, что в поле «Режим BIOS» указано **UEFI**, а через «Управление дисками» — что системный диск размечен как **GPT**. Если используется BitLocker / «Шифрование устройства», сохраните ключ восстановления доступным вне этого компьютера и при необходимости временно приостановите защиту по инструкции Windows. Без ключа или уверенности в схеме дисков выбирайте маршрут А.

1. **Подготовьте место в Windows.** В «Управлении дисками» уменьшите основной том Windows через **Shrink Volume / Сжать том** и оставьте **не менее 40 ГБ нераспределённого пространства**. Не создавайте на этом месте новый том в Windows, не форматируйте раздел EFI и не удаляйте раздел восстановления. Возможности уменьшения тома зависят от состояния диска; если Windows не даёт достаточно места, остановитесь и выбирайте ВМ вместо рискованных действий.
2. **Создайте установочную флешку.** Скачайте Debian **amd64 netinst ISO**. Запишите его на USB-накопитель, например через [Rufus](https://rufus.ie/) в Windows (схема разделов **GPT**, назначение **UEFI**). Проверьте выбранный USB-накопитель: запись удалит его прежнее содержимое. Полностью выключите Windows перед загрузкой с флешки; не продолжайте установку, если не подготовлены копия данных и нераспределённое место.
3. **Загрузите установщик в UEFI.** Через меню загрузки компьютера выберите пункт с флешкой, помеченный **UEFI**; не выбирайте вариант Legacy/CSM. В установщике Debian выберите **Graphical install**, язык, сеть, учётную запись. Как и для ВМ, при пустом пароле `root` первый пользователь получает `sudo`.
4. **Разместите Debian только в свободном месте.** В разделе разметки выберите автоматическую разметку **свободного нераспределённого места** (*guided — use largest continuous free space*, если этот вариант показан). **Никогда не выбирайте «Использовать весь диск» в этом маршруте.** Если выбора свободного места нет, остановитесь: не подменяйте его выбором всего диска. До записи изменений убедитесь, что системные разделы Windows (NTFS), раздел восстановления и уже существующий **EFI System Partition** не помечены для удаления или форматирования. Если план разметки непонятен — отмените установку и спросите преподавателя или администратора.
5. Выберите рабочий стол Debian и **standard system utilities**. Установите загрузчик GRUB в **режиме UEFI**; существующий EFI-раздел Windows можно использовать для загрузочных файлов **без форматирования**. После установки извлеките флешку и перезагрузите компьютер. Выберите Debian в меню загрузки. Убедитесь, что Windows по-прежнему загружается через меню GRUB или меню UEFI компьютера. Если после изменений Windows просит ключ BitLocker, используйте сохранённый ключ; после проверок возобновите приостановленную защиту.

Загрузчик, названия дисков и состав разделов зависят от конкретного ПК. Не продолжайте установку, если в итоговом списке есть форматирование раздела Windows или существующего EFI-раздела. Подготовка свободного места через «Управление дисками» описана в [документации Microsoft](https://learn.microsoft.com/en-us/windows-server/storage/disk-management/shrink-a-basic-volume); возможности разметки — в [руководстве установщика Debian](https://www.debian.org/releases/stable/amd64/ch06s03.en.html).

## Маршрут В. Mac с Apple Silicon: Debian arm64 в UTM

1. Установите [UTM](https://getutm.app/) на Mac и скачайте Debian **arm64 netinst ISO** с официальной страницы Debian. Не выбирайте ISO `amd64`: UTM будет *виртуализировать* ARM-процессор, а не эмулировать x86-64.
2. В UTM нажмите **+**, выберите **Virtualize → Linux** и подключите скачанный ISO. Выделите, если позволяет Mac, около **4096 МБ ОЗУ**, **2 ядра** и виртуальный диск не меньше **30 ГБ**. Проверьте, что выбран режим **Virtualize**, а не **Emulate**. Имена некоторых переключателей зависят от версии UTM.
3. Запустите ВМ. В установщике Debian выберите **Graphical install** (если графический режим недоступен, используйте **Install** с теми же шагами), задайте язык, сеть, обычного пользователя. Оставьте пароль отдельного `root` пустым, чтобы первому пользователю был доступен `sudo`.
4. Для разметки разрешается «Использовать весь диск» **только на виртуальном диске UTM**. Выберите рабочий стол Debian и **standard system utilities**, завершите установку загрузчика на виртуальный диск и перезагрузите ВМ. Извлеките ISO из виртуального привода, если снова появляется установочное меню, и войдите в Debian.

Выбор архитектуры влияет на дальнейшие задания: `uname -m` ниже покажет **`aarch64`** (название архитектуры Debian — `arm64`). Компилятор GCC соберёт обычную C-программу из этой работы. Исходники NASM для x86-64 и проверки курса, зависящие от **Linux x86-64**, нельзя запускать как обычные arm64-программы; для них понадобится другая x86-64-среда. Интерфейс создания ВМ описан в [документации UTM](https://docs.getutm.app/basics/basics/).

## Общая практика: первый вход и терминал

В Debian с графическим рабочим столом найдите приложение **Терминал** или попробуйте **Ctrl+Alt+T** (сочетание зависит от окружения). Если выбрали текстовую установку, войдите под именем своего пользователя: приглашение оболочки уже находится перед вами. При наборе пароля символы обычно не показываются. Не копируйте знак `$` из примеров приглашения, вводите только команды.

```sh
whoami
uname -m
pwd
ls -la
mkdir -p ~/aiya/debian-first-steps
cd ~/aiya/debian-first-steps
pwd
touch notes.txt
nano notes.txt
cat notes.txt
```

`whoami` покажет вашу учётную запись, `uname -m` — архитектуру гостя (`x86_64` на Windows-маршрутах, `aarch64` на Mac-маршруте). `pwd` показывает текущий каталог, `ls -la` — имена файлов, включая скрытые; `~` означает домашний каталог. `mkdir -p` создаст каталоги, `cd` перейдёт в рабочий каталог, `touch` создаст пустой файл. В nano запишите строку «Я работаю в Debian», сохраните **Ctrl+O**, **Enter**, выйдите **Ctrl+X**. `cat notes.txt` должен вывести введённую строку. Если `pwd` не заканчивается на `/aiya/debian-first-steps`, вернитесь командой `cd ~/aiya/debian-first-steps` перед продолжением.

Теперь подготовьте программы для учебных заданий. Команды с `sudo` могут попросить пароль вашего пользователя:

```sh
sudo apt update
sudo apt install build-essential gdb nasm binutils nano file
gcc --version
make --version
gdb --version
nasm -v
```

`apt update` обновляет список доступных пакетов, `apt install` устанавливает инструменты. `build-essential` включает GCC, `make` и файлы, необходимые для сборки C; `gdb` — отладчик, `nasm` — ассемблер x86, `binutils` — набор утилит (включая `ld`), `file` определяет тип файла. На Debian arm64 наличие NASM **не превращает** гостевую систему в x86-64. Сравните версии программ с выводом — точные числа зависят от даты установки. Если `sudo` сообщает, что пользователь не имеет прав, проверьте, как была создана учётная запись при установке; обратитесь за помощью вместо изменения системных настроек наугад.

## Соберите и запустите первую программу C

Оставайтесь в рабочем каталоге. Введите `nano hello.c`, наберите текст **вручную** и сохраните его. При просмотре в PDF обратите внимание на точки с запятой и двойные кавычки:

```c
#include <stdio.h>

int main(void)
{
    printf("Hello from C!\n");
    return 0;
}
```

Выполните сборку и проверку:

```sh
gcc -std=c11 -Wall -Wextra hello.c -o hello_c
./hello_c
echo $?
file hello_c
```

GCC получает текст `hello.c` и создаёт исполняемый файл `hello_c`; флаги `-Wall -Wextra` включают полезные предупреждения, `-o` задаёт имя результата. `./hello_c` просит Linux запустить программу из текущего каталога: ожидается **`Hello from C!`**. `echo $?` сразу после её запуска покажет **`0`** — код успешного завершения из `return 0;`. Важно выполнить `echo $?` **до** следующей команды: после `file hello_c` будет показан уже код завершения программы `file`. Утилита `file` распознает исполняемый ELF-файл; детали вывода будут различаться между архитектурами `x86-64` и `AArch64`.

Если вместо результата видите `command not found`, проверьте имя команды и установку пакета; для локального `hello_c` нужен префикс `./`. Для `No such file or directory` проверьте `pwd` и `ls -la`: возможно, вы не в том каталоге или опечатались в имени. Если GCC сообщил о синтаксической ошибке, прочитайте указанные файл и строку, проверьте кавычки и `;`, исправьте исходник в nano и **пересоберите**, прежде чем запускать программу снова. Результат `Permission denied` проверяйте через `ls -l hello_c`: файл после GCC обычно уже исполняемый, поэтому сначала выясните причину, а не применяйте `sudo` к своей программе.

## Что показать в отчёте

Укажите выбранный маршрут и обоснуйте его с помощью таблицы плюсов и минусов. Зафиксируйте, как вы выбрали **виртуальный** или **нераспределённый реальный** диск, что увидели при первой загрузке, и результаты `whoami`, `uname -m`, `pwd`, `ls -la`, установки инструментов и сборки. Запишите ожидаемый и наблюдаемый вывод `hello_c`, код завершения и одну возникшую трудность либо явно сообщите, что ошибок не было. Отправьте отчёт преподавателю **в PDF или HTML**, а `hello.c` сохраните отдельно, чтобы повторить сборку и запуск на защите.
