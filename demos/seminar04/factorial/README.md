## Напишите первую версию в nano

Введите `nano factorial.c` и наберите код **вручную**, не копируя готовый файл:

```c
#include <stdio.h>

unsigned long long factorial(unsigned int n)
{
    unsigned long long result = 1;
    for (unsigned int i = 1; i <= n; ++i) {
        result *= i;
    }
    return result;
}

int main(void)
{
    int n = 5;
    unsigned long long value = factorial((unsigned int)n);
    printf("factorial(%d) = %llu\n", n, value);
    return 0;
}
```

Сохраните файл клавишами **Ctrl+O**, **Enter**, выйдите через **Ctrl+X**. Внизу nano запись `^O` означает Ctrl+O. Проверьте наличие файла через `ls` и при желании прочитайте его через `cat factorial.c`.

`main` — начало программы. `factorial` умножает числа от 1 до `n`; переменная `result` начинается с 1, поэтому при `n = 0` цикл не выполнится и получится `0! = 1`. `unsigned long long` хранит беззнаковое целое большой разрядности. `printf` печатает в стандартный вывод: `%d` соответствует `int`, `%llu` — `unsigned long long`, `\n` завершает строку. После исполнения `return 0` сообщает оболочке об успешном завершении.

## Соберите и запустите программу

```sh
gcc -std=c11 -Wall -Wextra -Wpedantic -g -O0 \
  factorial.c -o factorial
./factorial
echo $?
```

Ожидаемый вывод: `factorial(5) = 120`, затем `0` от `echo $?` (смотрите код завершения **сразу после** запуска программы). Если `gcc` напечатал ошибку, найдите строку и исправьте код; при неуспешной сборке **не запускайте старый** файл `factorial`. Оболочка ищет программы в каталогах `PATH`, поэтому исполняемый файл в текущем каталоге запускаем через `./factorial`.

| Флаг GCC | Что делает |
|---|---|
| `-std=c11` | Выбирает стандарт языка C11. |
| `-Wall` | Включает распространённые предупреждения. |
| `-Wextra` | Включает дополнительные предупреждения. |
| `-Wpedantic` | Предупреждает об отклонениях от выбранного стандарта языка. |
| `-g` | Добавляет информацию для отладчика: имена функций и строки исходника. |
| `-O0` | Выключает оптимизацию, чтобы проще сопоставлять код с шагами GDB. |
| `-o factorial` | Задаёт имя исполняемого файла; без него GCC обычно создаёт `a.out`. |

Позже можно попробовать `-Werror` (считать предупреждения ошибками), `-O2` (оптимизировать программу; при отладке отображение переменных может измениться) и `-c` (получить объектный файл без линковки и готовой программы). Для основного опыта оставьте `-g -O0`.

Файл `factorial.c` — текст исходника на диске; `factorial` после успешной сборки — исполняемый файл на диске. При `./factorial` Linux создаёт **процесс**. После изменения `.c` старая исполняемая программа не меняется, пока вы не повторите сборку GCC.

## Измените программу через Vim и добавьте ввод

Сначала посмотрите редактор на знакомом файле: `vim factorial.c`. Vim открывается в **обычном режиме**: нажмите `i` для режима вставки и исправьте `int n = 5;` на `int n = 6;`. Нажмите **Esc**, затем наберите `:wq` и **Enter** — сохранить и выйти. Пересоберите и запустите: ожидается `factorial(6) = 720`. Полезные команды из обычного режима: `:w` сохраняет без выхода, `:q` выходит при отсутствии несохранённых правок, `:q!` выходит **без сохранения**. Если буквы не вводятся в файл, вы остались в обычном режиме: нажмите `i`.

Теперь снова откройте `vim factorial.c` (или `nano factorial.c`) и **замените содержимое** следующим кодом. Он читает одно целое число и явно разделяет обычный результат и ошибки:

```c
#include <stdio.h>

unsigned long long factorial(unsigned int n)
{
    unsigned long long result = 1;
    for (unsigned int i = 1; i <= n; ++i) {
        result *= i;
    }
    return result;
}

int main(void)
{
    int n;
    if (fscanf(stdin, "%d", &n) != 1) {
        fprintf(stderr, "Ошибка ввода.\n");
        return 1;
    }
    if (n < 0 || n > 20) {
        fprintf(stderr, "Нужно 0..20.\n");
        return 1;
    }
    unsigned long long value = factorial((unsigned int)n);
    printf("factorial(%d) = %llu\n", n, value);
    return 0;
}
```

Сохраните изменения и **снова выполните команду GCC**. Запустите `./factorial`, введите `5` и нажмите Enter: результат должен быть `factorial(5) = 120`. Проверьте `0`, `1`, `10`, `20`, `-1`, `21`, буквы вместо числа и пустой ввод (для конца ввода в интерактивном терминале нажмите **Ctrl+D** на пустой строке). Сравните с таблицей:

| Ввод | Ожидаемое поведение |
|---|---|
| `0`, `1` | `factorial(0) = 1`, `factorial(1) = 1` |
| `5`, `10` | `120`, `3628800` соответственно |
| `20` | `2432902008176640000` |
| `-1`, `21`, буквы, конец ввода | Сообщение об ошибке, ненулевой код завершения |

Число `20!` помещается в обычный 64-битный `unsigned long long`, а `21! = 51090942171709440000` больше максимально представимого значения `18446744073709551615`; поэтому программа ограничивает ввод. Данный учебный пример читает **первое целое число типа `int`**, а не проверяет всю строку: после `5` лишний текст не распознаётся как ошибка. Ввод числа вне диапазона `int` тоже не рассчитан на обработку этим простым вариантом `fscanf`; не выдавайте такую проверку за полную защиту от любого ввода.

## Файлы и три стандартных потока

Файл — последовательность байтов, сохраняемая файловой системой. Текстовый исходник, исполняемый файл и `input.txt` — разные файлы; расширение `.c` само по себе не делает файл исполняемым. Программа на C работает с потоком `FILE *` (абстракция стандартной библиотеки), который может читать из терминала или файла и писать в терминал или файл. В Linux у процесса при запуске обычно открыты стандартные дескрипторы: 0 (ввод), 1 (вывод), 2 (ошибки). Объекты C `stdin`, `stdout`, `stderr` связаны с этими потоками, но `FILE *` — **не номер дескриптора**.

`fscanf(stdin, "%d", &n)` читает число из стандартного ввода и возвращает количество успешно прочитанных значений (здесь нужно `1`). Упрощённая запись — `scanf("%d", &n)`; в обоих случаях нужен адрес `&n` и проверка результата. `printf(...)` пишет в `stdout`, то же можно записать `fprintf(stdout, ...)`. `fprintf(stderr, ...)` пишет в отдельный поток ошибок. Эти функции **выводят** данные; для ввода служат `scanf`/`fscanf`.

Скопируйте `input.txt` из комплекта материалов в рабочий каталог или создайте его командой `nano input.txt` и запишите число `5`. Если вы работаете без архива, достаточно варианта с nano. Затем выполните:

```sh
./factorial < input.txt > output.txt 2> errors.txt
echo $?
cat output.txt
cat errors.txt
```

`<` подаёт файл в `stdin`, `>` сохраняет `stdout` (при повторе **перезаписывает** файл), `2>` сохраняет `stderr`. Ожидайте ответ в `output.txt` и пустой `errors.txt`. Измените `input.txt` на `21`, повторите запуск и **сразу** проверьте `echo $?`: теперь `output.txt` пуст, а сообщение — в `errors.txt`. `>>` добавляет вывод к существующему файлу вместо перезаписи. Перенаправления оболочки влияют на запущенную программу; диагностические сообщения самого GCC при сборке — отдельный запуск другого процесса.

## Найдите ошибку в GDB

Восстановите в `input.txt` число `5` и **снова соберите** программу с `-g -O0`: `-g` сохраняет имена переменных и соответствие строк исходнику, а `-O0` не даёт оптимизатору переставить или убрать интересующие нас вычисления. Работайте из каталога с `factorial.c`, `factorial` и `input.txt`. Сначала в **обычной оболочке** наберите:

```sh
gdb -q ./factorial
```

`-q` скрывает вводный баннер. Появится приглашение **`(gdb)`**; дальнейшие команды вводите уже *в отладчике*, без текста `(gdb)`. Выражение `./factorial` — путь к исполняемому файлу, а не команда внутри GDB. На остановке GDB показывает строку, которую программа **собирается выполнить**: до первого `next` значение ещё не инициализированной локальной переменной читать нельзя. Номера строк ниже относятся к показанному выше коду; если вы добавляли строки в `factorial.c`, номера сдвинутся.

### Шаг 1. Остановитесь в функции

```text
break factorial
info breakpoints
run < input.txt
print n
info args
backtrace
```

`break factorial` ставит точку останова на входе в функцию. GDB сообщает её **номер** (`Breakpoint 1`) и строку. `info breakpoints` показывает номера, состояние и места всех остановок; используйте реальные номера, которые видите у себя. Можно ставить остановку и по строке, например `break factorial.c:7` — это строка `result *= i;` в исходнике из методички. Не добавляйте её пока, чтобы не изменить следующий опыт.

`run < input.txt` **начинает новый запуск** программы: `<` подаёт файл в её стандартный ввод. Отладчик остановится в `factorial` до выполнения строки `unsigned long long result = 1;`. В сообщении `Breakpoint ... factorial (n=5) ...` важны функция, аргумент, имя файла и текущая строка; адреса и номера внутренних кадров могут отличаться. Если забыть `< input.txt`, программа может ждать число в терминале: введите `5` и Enter либо прервите выполнение клавишами **Ctrl+C** и повторите `run < input.txt`.

`print n` покажет значение аргумента `5`. Запись вида `$1 = 5` — это номер **результата команды `print` в истории GDB**, а не переменная C и не код завершения `$?` из оболочки. `info args` перечислит аргументы текущей функции. `backtrace` (или `bt`) покажет цепочку вызовов: `#0 factorial` — где мы остановились, `#1 main` — кто вызвал функцию. Команда `frame 1` выбирает кадр `main` для просмотра его переменных, `frame 0` возвращает контекст просмотра в `factorial`; сами эти команды **не выполняют программу**. Находясь в `main`, можно посмотреть его `n`, а `result` там недоступна.

### Шаг 2. Выполняйте строки

Убедитесь, что выбран `frame 0`, затем введите:

```text
next
print result
info locals
next
print i
next
print result
```

Первый `next` выполнит `result = 1` и поставит указатель на заголовок `for`; теперь `print result` выдаёт `1`. `info locals` показывает доступные локальные переменные, но на заголовке `for` значение `i` до инициализации не следует считать результатом вычисления. Следующий `next` войдёт в первую итерацию и остановится перед `result *= i`: здесь `print i` покажет `1`. Ещё один `next` выполнит умножение `1 × 1`, поэтому `result` всё ещё `1`. У цикла есть заголовок, тело и переход к следующей итерации: один `next` **не обязательно равен одной итерации**. Если вы оказались на другой строке, посмотрите на строку, которую показывает GDB, и выполните следующую команду осознанно.

`next` выполняет текущую строку, **не заходя внутрь** вызываемой функции; `step` на строке с вызовом заходит в неё. Для отдельного сравнения вернитесь в `main` новым запуском: `break main`, `run < input.txt`, затем делайте `next` до строки `value = factorial(...)` и введите `step` — вы попадёте в `factorial`. `finish` продолжит выполнение текущей функции до `return` и остановится в вызывающей функции, показав возвращённое значение. При `step` на строке `printf` можно попасть в код библиотеки; для первого опыта удобнее `next` или `finish`. Перед следующим опытом удалите временную точку `break main` командой `delete НОМЕР` (номер смотрите через `info breakpoints`). При каждом повторном `run` выполнение начинается заново, но остальные точки останова остаются до их удаления.

### Шаг 3. Следите за произведением

Проверьте через `info breakpoints`, что оставлена точка `break factorial`, но нет временной остановки в `main`. Начните новый запуск командой `run < input.txt`: при остановке на входе в `factorial` сначала выполните **`next`**, чтобы инициализировать `result`. Затем:

```text
watch result
info breakpoints
continue
print i
print result
continue
continue
continue
print result
```

`watch result` — **точка наблюдения**: GDB остановится, когда значение `result` *изменится*, и покажет `Old value` и `New value`. Первое умножение `1 × 1` не меняет `result`, поэтому первой новой величиной будет **2 при `i = 2`**. Затем повторные `continue` приведут к изменениям **2 → 6 → 24 → 120**. На последней остановке `print result` покажет `120`; следующее `continue` завершит программу с напечатанным ответом. Не пытайтесь читать `result` уже после завершения: локальная переменная существовала только во время вызова функции.

Для вывода значения на **каждой** остановке можно выполнить `display result`: GDB присвоит этому отображению номер и будет печатать значение автоматически, пока переменная доступна. Узнать номер можно через `info display`, отключить — `undisplay НОМЕР`. `display` лишь показывает значение, а `watch` останавливает выполнение при изменении. Список остановок и их номера показывает `info breakpoints`; `disable НОМЕР` временно выключает точку, `enable НОМЕР` включает обратно, `delete НОМЕР` удаляет её. Не подставляйте номер наугад: в список входят и `break`, и `watch`.

### Шаг 4. Исследуйте стек и память

После завершения предыдущего запуска локальная точка `watch result` перестаёт действовать, поскольку переменная вышла из области видимости. Снова запустите `run < input.txt`, остановитесь в `factorial`, выполните `next` для инициализации `result` и поставьте `watch result` заново. Четыре раза выполните `continue`: остановитесь на изменении с `24` на `120`. Пока вы внутри функции, выполните:

```text
backtrace
info locals
print sizeof(result)
print &result
x/8xb &result
```

`backtrace` снова покажет `#0 factorial` и `#1 main`. `info locals` позволяет сопоставить `i` и `result`. `sizeof(result)` в этой учебной среде x86-64 равен **8 байтам**. `&result` — адрес переменной в *виртуальной* памяти процесса: конкретное число не переписывайте в отчёт как универсальный адрес. В команде `x/8xb &result` буква **`x`** означает просмотр памяти, **`8`** — восемь элементов, следующий **`x`** — вывод в шестнадцатеричном виде, **`b`** — размер элемента в один байт. Для `result = 120` (`0x78`) на типичном Linux x86-64 ожидаются байты `0x78 0x00 0x00 0x00 0x00 0x00 0x00 0x00`: младший байт расположен первым (*little-endian*). В начале опыта при `result = 1` первым байтом будет `0x01`; не смешивайте две разные остановки. Не путайте `x/8xb` со стандартной командой оболочки или с выражением C.

### Шаг 5. Найдите ошибку в условии

Выйдите из GDB командой `quit`. Через nano или Vim **намеренно** измените условие в цикле на `i < n` и пересоберите с `-g -O0`. Для ввода `5` программа теперь выдаёт **24** вместо 120: последний множитель не используется. Снова откройте GDB и остановитесь непосредственно **перед умножением**:

```text
break factorial.c:7
run < input.txt
print i
print result
continue
```

Повторяйте `print i` и `continue` на остановках: до строки `result *= i;` вы дойдёте при `i = 1, 2, 3, 4`, но **не при `i = 5`**. Если строки в вашем файле сдвинулись, поставьте точку по актуальному номеру строки умножения (`list factorial` показывает исходник) или на входе в `factorial` и идите через `next`. Запишите, какие значения наблюдали и почему ответ равен 24. Восстановите `i <= n`, **пересоберите** программу и повторите проверку для `0`, `5` и `20`. Менять ожидаемый ответ вместо исправления цикла нельзя.

Если GDB пишет `No symbol ... in current context`, проверьте, остановлена ли программа **внутри нужной функции**: например, `i` видна только в области действия цикла, а после завершения процесса локальные переменные недоступны. Сообщение `The program is not being run` означает, что нужно выполнить `run`. Если GDB не знает имён и строк исходника, проверьте сборку с `-g` и то, что отлаживаете **заново собранный** `./factorial`. Если вывод отладчика отличается, попробуйте `help КОМАНДА` (например, `help watch`); `quit` закрывает GDB, а `Ctrl+C` прерывает ожидающую ввода или работающую программу.

| Команда | Краткая памятка |
|---|---|
| `break`, `info breakpoints` | Остановиться в функции или на строке, показать точки и их номера. |
| `run`, `continue` | Запустить сначала с вводом из файла; продолжить текущий запуск. |
| `next`, `step`, `finish` | Выполнить строку без захода в вызов, войти в функцию, завершить функцию. |
| `print`, `info args`, `info locals` | Узнать значение выражения, аргументы и локальные переменные. |
| `watch`, `display` | Остановиться при изменении; показать значение при остановках. |
| `backtrace`, `frame` | Показать стек вызовов и выбрать кадр для просмотра. |
| `x/8xb`, `help`, `quit` | Прочитать восемь байтов памяти, открыть справку, выйти из GDB. |
