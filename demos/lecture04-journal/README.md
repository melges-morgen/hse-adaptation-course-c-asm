# Журнал оценок: BIOS и 16-битный NASM

Действующая программа написана на 16-битном NASM и выполняется в **real mode**
QEMU PC (i440FX) без гостевой ОС. BIOS запускает первый сектор виртуальной
дискеты (512 байтов) по адресу `0000:7C00`; `boot16.asm` читает следующие
17 секторов в `1000:0000` и передаёт управление `journal16.asm`. Компилятор C,
GRUB, переход в long mode и страничные таблицы здесь не используются.
В слайдах C помогает объяснить алгоритм, но в QEMU исполняется только NASM.

Оборудование: 16 MiB RAM, VGA text (сегмент `B800h`), PS/2, BIOS,
совместимый PIC, COM1 для машинных тестов, загрузочная дискета 1.44 MiB и
отдельный IDE-диск 1 MiB с оценками. Текущий исходник (`journal16.asm`)
не должен превышать 17 × 512 байтов: сборка проверяет размер и сигнатуру
`55 AA` первого сектора.

## Сборка и запуск

Из корня репозитория:

```sh
make lecture4-journal-check            # собрать шесть стадий и проверить QEMU
make lecture4-journal-run              # версия 6, http://localhost:6080/vnc.html
make lecture4-journal-run STAGE=3      # ввод через сервис BIOS INT 16h
```

Сборка и запуск выполняются внутри Docker; на хосте достаточно Docker и make.
Откройте указанный адрес noVNC, нажмите Connect при необходимости и щёлкните
по экрану для ввода. Для завершения QEMU — Ctrl+C в терминале.
Данные диска хранятся в `build/lecture04-journal/grades.img` между запусками.
При переходе со старой x86-64-версии сохранение `GRD4` распознаётся как
`BAD_FORMAT`; удаление/сброс образа данных создаёт новый пустой журнал.

Студенты — `S01`–`S16`, работы — `W1`–`W4`. Стрелки выбирают поле; 0–9
выставляют оценки; `A` задаёт 10; Backspace убирает оценку (`FF`, отдельно
от настоящего нуля). На шестой стадии `S` сохраняет, `L` загружает.
Сервис BIOS и обработчик IRQ возвращают разные формы кода стрелки;
`handle_scan` учитывает оба пути. В текстовом VGA применены латинские
идентификаторы; русские пояснения даны в пособии и слайдах.

| Стадия | Возможность | Аппаратный механизм |
|---|---|---|
| 1 | строка `S01 grade 07` | boot sector, BIOS INT 13h/10h |
| 2 | таблица 16×4 | NASM-массив, прямая запись в VGA |
| 3 | ввод/исправление | клавиатурный сервис BIOS INT 16h |
| 4 | свой обработчик клавиши | IVT, аппаратный IRQ1, очередь |
| 5 | статистика по оценкам | регистры, целочисленная арифметика |
| 6 | сохранение/восстановление | BIOS INT 13h Extensions, отдельный диск |

## Маршрут показа

| Теория | Код | Наблюдение |
|---|---|---|
| BIOS и CS:IP | `boot16.asm` | `BOOT STAGE=1`, затем `READY` |
| Программное INT | `journal16.asm:bios_text` | `S01 grade 07` |
| Адреса и данные | `grades`, `redraw`, `vga_text` | 16 строк и четыре работы |
| Скан-коды | `INT 16h`, `handle_scan` | ввод 0/10, удаление оценки |
| Внешнее прерывание | `install_irq1`, `irq1`, `dequeue` | те же действия без BIOS INT 16h |
| Среднее | `report_grade`, `redraw` | 0 и 10 → `AVG=5.00` |
| Блочное хранение | `save_grades`, `disk_io`, `load_grades` | `SAVED`, новый запуск, `LOADED` |

COM1 — диагностический канал теста, а VGA — экран пользователя. Автоматическая
проверка `check.py` отправляет клавиши через монитор QEMU и сверяет COM1.
Тестируются 0/10, 0.67, исправление/очистка, загрузка после перезапуска,
повреждённые данные, несовместимая версия и отсутствие диска. Время работы
QEMU не используется для выводов о производительности настоящего кэша.

## Формат одного сектора данных (LBA 1 первого HDD)

| Смещение | Байты |
|---|---|
| 0–3 | ASCII `GR16` |
| 4–7 | версия 1, 16 студентов, 4 работы, резерв 0 |
| 8–71 | 64 оценки 0–10 либо `FF` |
| 72–73 | сумма байтов 0–71 modulo 65536, little-endian |
| 74–511 | нули |

Сохраняем сектор, а не именованный файл; нет файловой системы. Загрузка
сначала проверяет заголовок, версию, сумму и все оценки, затем заменяет
таблицу RAM. Сохранение в одну копию сектора не является атомарным при
внезапном выключении. BIOS реализует операции чтения/записи контроллера;
собственный ATA PIO-драйвер в этой версии не используется. Прежний код
x86-64 сохранён только для исторического сравнения в `legacy/`.
